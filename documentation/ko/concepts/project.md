# 프로젝트(Project): 프로젝트 템플릿

### 개념 정의

**프로젝트**는 구체적인 작업이나 목표로, 명확한 시작과 종료 시간, 그리고 측정 가능한 결과가 있습니다. 프로젝트 템플릿은 특정 유형의 프로젝트를 완료하기 위한 표준 프로세스와 방법을 정의합니다.

### 핵심 요소

#### 기본 정보
- **프로젝트 이름**: 프로젝트의 식별 이름
- **프로젝트 설명**: 상세한 프로젝트 소개
- **프로젝트 상태**: 계획 중 / 진행 중 / 완료 / 보관됨
- **시작 시간**: 프로젝트의 시작 시간
- **종료 시간**: 프로젝트의 예상 완료 시간
- **우선순위**: 낮음 / 중간 / 높음 / 긴급

#### 프로젝트 구조
- **단계 분류**: 프로젝트가 어떤 단계로 나뉘는지 (예: 요구, 설계, 개발, 테스트, 배포)
- **마일스톤**: 중요한 검토점과 인도물
- **작업 분해**: WBS(작업 분해 구조)
- **종속 관계**: 작업 간의 종속 관계

#### 표준 작업 프로세스(SOP)
- **단계 프로세스**: 각 단계의 표준 작업 단계
- **인도물 목록**: 각 단계에서 생산해야 할 문서와 결과
- **검수 표준**: 각 단계의 완료 표준과 품질 요구 사항
- **승인 노드**: 승인이 필요한 중요 노드

#### 자원 구성
- **책임 팀**: 프로젝트는 동시에 하나의 팀에게만 맡길 수 있음
- **필요 기술**: 어떤 기술을 가진 직원이 필요한지
- **시간 추정**: 각 단계의 시간 추정
- **예산 계획**: 프로젝트의 예산 할당

#### 팀과 서브 팀
- **단일 팀 책임**: 각 프로젝트는 동시에 하나의 주 책임 팀만 가질 수 있음
- **서브 팀 호출**: 주 팀은 필요에 따라 서브 팀을 호출할 수 있음
- **유연한 조합**: 서브 팀은 완전한 팀이어야 하며, 하나의 직원만 있더라도 팀으로 포장해야 함
- **협업 메커니즘**: 주 팀과 서브 팀 사이에 명확한 협업과 소통 방식이 있음

#### 리스크 관리
- **리스크 식별**: 만날 수 있는 리스크
- **대응 전략**: 리스크의 대응 방안
- **비상 계획**: 긴급 상황의 처리 계획
- **품질 표준**: 프로젝트의 품질 요구 사항

### 프로젝트 템플릿의 역할

1. **표준화된 프로세스**
   - 동일한 유형의 프로젝트는 동일한 프로세스를 사용
   - 반복 작업을 줄이고 효율성을 높임
   - 프로젝트 품질의 일관성 확보

2. **경험 축적**
   - 성공적인 프로젝트는 템플릿으로 전환될 수 있음
   - 실패 경험은 템플릿 개선에 반영될 수 있음
   - 조직의 프로젝트 관리 능력이 지속적으로 향상

3. **협업 효율성**
   - 팀원이 각 단계의 목표를 명확히 이해
   - 소통 비용을 줄임
   - 신입이 빠르게 적응할 수 있음

### 예시: 제품 개발 프로젝트 템플릿

```
제품 개발 프로젝트
├── 단계 1: 요구 조사
│   ├── 시장 분석
│   ├── 사용자 인터뷰
│   ├── 경쟁 제품 분석
│   └── 요구 문서
├── 단계 2: 제품 설계
│   ├── 제품 프로토타입
│   ├── UI 설계
│   ├── 인터랙션 설계
│   └── 설계 검토
├── 단계 3: 개발 구현
│   ├── 아키텍처 설계
│   ├── 코드 개발
│   ├── 단위 테스트
│   └── 코드 검토
├── 단계 4: 테스트 검증
│   ├── 기능 테스트
│   ├── 성능 테스트
│   ├── 사용자 테스트
│   └── Bug 수정
└── 단계 5: 배포 출시
    ├── 배포 준비
    ├── 회색 배포
    ├── 전체 배포
    └── 효과 모니터링
```
