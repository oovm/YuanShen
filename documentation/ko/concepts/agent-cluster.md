# 팀(Team): Agent Groups

### 개념 정의

**팀**은 함께 일하는 에이전트(Agent) 그룹으로, 공동의 목표를 위해 협업합니다. 팀은 에이전트 간의 역할 분업, 협업 방식 및 소통 규칙을 정의합니다.

### 핵심 요소

#### 기본 정보
- **팀 이름**: 팀의 식별 이름
- **팀 설명**: 상세한 팀 소개
- **팀 유형**: 기능형 / 프로젝트형 / 매트릭스형 / 가상형
- **팀 멤버**: 팀에 포함된 에이전트 목록

#### 역할 분업
- **팀 리더**: 전체 조정과 의사 결정을 담당
- **전문가 멤버**: 특정 분야의 전문 작업을 담당
- **조정 멤버**: 팀 내외의 소통 조정을 담당
- **지원 멤버**: 보조적인 지원 작업을 제공

#### 협업 모드
- **보고 관계**: 누가 누구에게 보고하는지
- **의사 결정 메커니즘**: 어떻게 의사 결정을 내리는지
- **소통 채널**: 어떤 방식으로 소통하는지
- **회의 리듬**: 정기 회의의 일정

#### 팀 문화
- **협업 원칙**: 팀 멤버가 어떻게 협업하는지
- **충돌 처리**: 의견 차이와 충돌을 어떻게 처리하는지
- **지식 공유**: 지식과 경험을 어떻게 공유하는지
- **팀 정신**: 팀의 응집력 구축

#### 서브 팀 관리
- **서브 팀 개념**: 팀은 서브 팀을 포함할 수 있으며, 서브 팀은 완전한 팀이어야 함
- **서브 팀 호출**: 팀은 필요에 따라 서브 팀을 호출하여 특정 작업을 완료할 수 있음
- **유연한 구성**: 서브 팀은 완전한 팀이어야 하며, 하나의 에이전트만 있더라도 팀으로 포장해야 함
- **계층 협업**: 여러 레벨의 서브 팀 중첩과 협업을 지원

### 팀 템플릿의 역할

1. **최적의 조합**
   - 작업 요구를 기반으로 적합한 에이전트 조합을 선택
   - 다른 기술을 가진 에이전트가 상호 보완
   - 1+1>2의 협업 효과를 형성

2. **협업 규범**
   - 명확한 역할과 책임
   - 표준화된 협업 프로세스
   - 협업 마찰을 줄임

3. **재사용성**
   - 성공적인 팀 구성을 템플릿으로 저장할 수 있음
   - 유사한 작업에 동일한 팀을 직접 사용할 수 있음
   - 빠르게 효율적인 팀을 구성

### 예시: 제품 개발 팀 템플릿

```
제품 개발 팀
├── 제품 관리자 (AI)
│   ├── 역할: 팀 리더
│   ├── 책임: 요구 분석, 우선순위 정렬, 진행 관리
│   └── 기술: 제품 사고, 사용자 연구, 프로젝트 관리
├── 아키텍트 (AI)
│   ├── 역할: 기술 전문가
│   ├── 책임: 시스템 설계, 기술 선택, 코드 검토
│   └── 기술: 시스템 아키텍처, 설계 패턴, 기술 트렌드
├── 개발자 (AI)
│   ├── 역할: 실행 멤버
│   ├── 책임: 코드 구현, 단위 테스트, 문서 작성
│   └── 기술: 프로그래밍 언어, 프레임워크 사용, 베스트 프랙티스
├── 테스터 (AI)
│   ├── 역할: 품질 보증
│   ├── 책임: 테스트 계획, 테스트 실행, Bug 추적
│   └── 기술: 테스트 방법, 품질 표준, 자동화 테스트
└── 운영자 (AI)
    ├── 역할: 운영 지원
    ├── 책임: 배포 구성, 모니터링 알림, 장애 처리
    └── 기술: DevOps, 클라우드 서비스, 시스템 관리
```
