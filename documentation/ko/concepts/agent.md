# 직원(Employee): Agent

직원(Employee)은 **기술 집합**으로 구성된 에이전트(Agent)로, 에이전트가 무엇을 할 수 있고, 무엇을 잘하고, 그리고 다른 에이전트와 어떻게 협업하는지를 정의합니다.

## 개념 정의

**직원**은 기술의 컨테이너와 조합체로, 다른 기술을 조합하여 완전한 작업 능력을 형성합니다. 직원 자체는 기술이 아니라 기술의 집합입니다.

## 핵심 요소

### 기본 정보

- **직원 이름**: 에이전트의 식별 이름
- **직원 아바타**: 시각적 식별자
- **직위**: 에이전트의 역할 포지셔닝
- **설명**: 상세한 능력 소개
- **역할 유형**: 에이전트의 역할 분류

### 기술 집합

직원은 여러 기술을 조합하여 작업 능력을 형성합니다:

- **핵심 기술**: 기본 능력(소통, 추론, 학습, 기억 등)
- **전문 기술**: 특정 분야의 전문 능력(프로그래밍, 분석, 디자인 등)
- **도구 기술**: 특정 도구를 사용하는 능력(개발 도구, 디자인 도구, 사무 도구 등)
- **소프트 스킬**: 대인 관계와 팀 협업 능력

자세한 기술体系는 [skills.md](skills.md)를 참고하세요.

### 능력 구성

직원은 여러 능력을 구성하여 기능을 확장할 수 있습니다:

- **API 통합 능력**: 외부 API를 호출하는 능력
- **MCP 서비스 능력**: MCP(Model Context Protocol) 서비스를 사용하는 능력
- **파일 조작 능력**: 파일을 읽고 쓰는 능력
- **네트워크 액세스 능력**: 네트워크 리소스에 액세스하는 능력

자세한 능력体系는 [capabilities.md](capabilities.md)를 참고하세요.

### 작업 스타일

- **응답 속도**: 빠른 응답 / 신중한 고려
- **의사 결정 방식**: 결단력 있게 의사 결정 / 충분한 상담
- **소통 스타일**: 간결하고 직접적 / 상세히 설명
- **리스크 선호**: 모험을 감수 / 신중하고 보수적

## 직원의 역할

### 1. 기술 조합

- 여러 기술을 조합하여 완전한 작업 능력을 형성
- 기술 간에 협력하여 합력을 형성
- 다양한 작업 시나리오에 유연하게 대응

### 2. 능력 표준화

- 에이전트의 능력 경계를 명확히 정의
- 사용자가 적합한 에이전트를 선택하기 쉽게 함
- 다른 에이전트를 평가하고 비교할 수 있음

### 3. 지속적인 진화

- 에이전트가 새로운 기술을 학습할 수 있음
- 기술이 지속적으로 향상되고 최적화될 수 있음
- 새로운 능력 확장을 추가할 수 있음
- 새로운 요구와 시나리오에 적응

## 예시: 풀스택 개발자 에이전트

```
풀스택 개발자 (Alex)
├── 기본 정보
│   ├── 이름: Alex
│   ├── 직위: 시니어 풀스택 개발 엔지니어
│   └── 소개: 5년 개발 경험, 웹 애플리케이션 개발에 능숙함
├── 기술 집합
│   ├── 핵심 기술
│   │   ├── 소통 능력: 고급
│   │   ├── 추론 능력: 전문가급
│   │   ├── 학습 능력: 고급
│   │   └── 기억 능력: 고급
│   ├── 전문 기술
│   │   ├── 프론트엔드 개발 (React/Vue/TypeScript): 전문가급
│   │   ├── 백엔드 개발 (Node.js/Python): 고급
│   │   ├── 데이터베이스 설계: 전문가급
│   │   └── API 설계: 고급
│   ├── 도구 기술
│   │   ├── Git: 전문가급
│   │   ├── VS Code: 전문가급
│   │   ├── Docker: 고급
│   │   └── CI/CD: 고급
│   └── 소프트 스킬
│       ├── 팀 협업: 고급
│       ├── 코드 검토: 전문가급
│       └── 기술 문서: 고급
├── 능력 구성
│   ├── API 통합 능력: 활성화
│   ├── MCP 서비스 능력: 활성화
│   ├── 파일 조작 능력: 활성화
│   └── 네트워크 액세스 능력: 활성화
└── 작업 스타일
    ├── 응답 속도: 빠른 응답
    ├── 의사 결정 방식: 결단력 있게 의사 결정
    ├── 소통 스타일: 상세히 설명
    └── 코드 스타일: 유지 보수성 중시
```
