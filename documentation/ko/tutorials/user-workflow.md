# 사용자 워크플로우

이 가이드는 사용자가 AI Company 시스템을 사용할 때의 완전한 워크플로우를 자세히 설명합니다.

## 1. 입문 단계

### 1.1 등록과 로그인
1. AI Company 공식 웹사이트 방문
2. 오른쪽 상단「로그인/등록」버튼 클릭
3. 사용자 이름, 이메일, 비밀번호 등록 정보 작성
4. 이메일 주소 인증
5. 등록한 계정으로 시스템 로그인

### 1.2 클라이언트 다운로드
1. 로그인 성공 후, 홈페이지「지금 시작」버튼 클릭
2. 운영 체제에 따라 해당 다운로드 버전 선택:
   - Windows(Windows 10/11 지원)
   - macOS(macOS 10.15+ 지원)
   - Linux(주요 배포판 지원)
3. 클라이언트 설치 및 시작

### 1.3 작업 노드 초기화
1. 클라이언트를 처음 시작하면 시스템이 자동으로 현재 디바이스를 작업 노드로 식별
2. 작업 노드 이름 설정(예:「내 노트북」,「집의 서버」)
3. 첫 번째 워크스페이스 생성(예:「개인 프로젝트」,「업무 프로젝트」)

## 2. 조직 아키텍처 구축

### 2.1 회사 템플릿 생성 또는 선택
1.「회사 관리」화면으로 이동
2. 적합한 회사 템플릿 선택:
   - **1인 회사**: 개인 창업자와 슈퍼 인디비주얼에 적합
   - **소규모 팀**: 3-10인 팀에 적합
   - **중소 기업**: 10-50인 기업에 적합
   - **맞춤형**: 처음부터 조직 아키텍처 구축
3.「1인 회사」템플릿을 선택하면 시스템이 자동으로 비서실과 필요한 조직 아키텍처를 생성

### 2.2 프로젝트 템플릿 구성
1.「프로젝트 관리」화면으로 이동
2. 새 프로젝트 템플릿 생성:
   - 프로젝트 이름과 설명 설정
   - 프로젝트 목표와 산출물 정의
   - 프로젝트 SOP(표준 작업 프로세스) 구성
   - 프로젝트 마일스톤과 시간 노드 설정
3. 또는 시스템 미리 설정된 프로젝트 템플릿 선택:
   - 제품 개발
   - 콘텐츠 창작
   - 시장 홍보
   - 고객 서비스

### 2.3 팀 구성
1.「팀 관리」화면으로 이동
2. 주 팀 생성
3. 필요에 따라 하위 팀 생성(단일 직원도 하위 팀으로 관리 가능)
4. 팀의 책임과 권한 범위 설정
5. 팀의 협업 프로세스 구성

### 2.4 직원(에이전트) 구성
1.「직원 관리」화면으로 이동
2. 에이전트 스킬 템플릿 생성 또는 선택
3. 에이전트에 스킬 구성:
   - 전문 스킬(예: 프로그래밍, 작문, 디자인)
   - 도구 사용 능력(예: Git, Figma, Photoshop)
   - 커뮤니케이션 스타일(예: 공식적, 간결함, 친절함)
   - 의사결정 모드(예: 자율적, 협의적, 보고적)
4. 에이전트를 해당 팀에 할당

## 3. 프로젝트 실행

### 3.1 프로젝트 시작
1.「프로젝트 실행」화면으로 이동
2. 실행할 프로젝트 템플릿 선택
3. 프로젝트를 하나의 팀에 할당(주의: 각 프로젝트는 동시에 하나의 팀에게만 맡길 수 있음)
4. 프로젝트의 구체적인 매개변수와 목표 설정
5. 프로젝트 시작

### 3.2 프로젝트 진행 모니터링
1. 프로젝트 대시보드를 보고 프로젝트 전체 진행 상황 파악
2. 팀의 작업 상태와 작업 할당 보기
3. 에이전트의 실행 상황과 산출물 보기
4. 프로젝트 마일스톤의 완료 상황 보기

### 3.3 개입과 조정
1. 필요할 경우 팀에 지시를 내리거나 피드백 제공
2. 프로젝트 매개변수나 시간 노드 조정
3. 다른 하위 팀을 호출하여 특정 작업 지원 완료
4. 비서실을 통해 프로젝트의 상세 보고서 얻기

### 3.4 프로젝트 수락
1. 프로젝트 완료 후, 최종 산출물 보기
2. 프로젝트 결과가 기대에 부합하는지 검토
3. 프로젝트 수락 확인
4. 프로젝트 경험과 모범 사례 저장

## 4. 여러 작업 노드와 워크스페이스 관리

### 4.1 새 작업 노드 추가
1. 새 디바이스에 AI Company 클라이언트 설치 및 로그인
2. 새 디바이스가 자동으로 새 작업 노드로 등록
3. 새 작업 노드의 이름과 설명 설정

### 4.2 워크스페이스 관리
1. 임의의 작업 노드에서 새 워크스페이스 생성
2. 워크스페이스 간에는 서로 격리되어 다른 프로젝트나 용도로 사용 가능
3. 다른 워크스페이스 간에 전환 가능
4. 워크스페이스의 권한과 액세스 제어 설정

### 4.3 노드 간 협업
1. 프로젝트가 여러 작업 노드 간에 분배될 수 있음
2. 에이전트가 다른 작업 노드에서 실행될 수 있음
3. 데이터가 작업 노드 간에 안전하게 동기화될 수 있음
4. 모든 작업 노드의 상태와 리소스 사용 상황을 모니터링 가능

## 5. 모범 사례

### 5.1 1인 회사 워크플로우 제안
1.「1인 회사」템플릿을 사용하여 비서실의 역할을 충분히 발휘
2. 여러 워크스페이스를 생성하여 다른 유형의 프로젝트에 각각 사용
3. 여러 전문 에이전트를 구성하여 다른 스킬 분야를 커버
4. 정기적으로 비서실을 통해 모든 에이전트의 작업 결과 검토

### 5.2 프로젝트 관리 제안
1. 다른 유형의 프로젝트에 대해 전용 프로젝트 템플릿 생성
2. 프로젝트 SOP를 상세히 정의하여 에이전트가 기대를 이해하도록 함
3. 합리적인 마일스톤을 설정하여 프로젝트 진행 모니터링 용이
4. 성공적인 프로젝트 경험을 보존하여 후속 프로젝트에 사용

### 5.3 에이전트 구성 제안
1. 실제 요구에 따라 에이전트의 스킬과 스타일 구성
2. 동일한 에이전트에 대해 여러 구성 버전을 생성하여 다른 시나리오에 사용
3. 에이전트의 작업 효과를 관찰하여 지속적으로 구성 최적화
4. 하위 팀 메커니즘을 활용하여 에이전트 간에 상호 협업하도록 함
