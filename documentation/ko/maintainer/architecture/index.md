AI Company는 명확한 3층 아키텍처 설계를 채택하며, 각 층은 명확한 책임과 경계를 가지고 있습니다.

### 각 층의 책임 설명

#### 1. 표현층(애플리케이션단)

표현층은 사용자가 직접 상호작용하는 인터페이스로, 다양한 애플리케이션과 프론트엔드 인터페이스를 포함합니다.

**주요 구성 요소:**
- `ai-company` - 메인 애플리케이션 백엔드
- `ai-empire` - 제국 모듈 백엔드
- `ai-planet` - 행성 모듈 백엔드
- `ai-waifu` - 캐릭터 모듈 백엔드
- Vue.js 프론트엔드 애플리케이션

**책임:**
- 사용자 인터페이스 제공
- 사용자 상호작용 처리
- 구현층의 핵심 모듈 호출
- 데이터 표시 및 수집

#### 2. 구현층(augur-* 핵심 모듈)

구현층은 시스템의 핵심 비즈니스 로직층으로, 여러 전문 기능 모듈을 포함합니다.

**주요 모듈:**
- `augur-agent` - 에이전트 관리
- `augur-orchestrator` - 오케스트레이터
- `augur-organization` - 조직 관리
- `augur-skill` - 스킬 관리
- `augur-memory` - 기억 시스템
- `augur-persistence` - 영속화
- `augur-file-system` - 파일 시스템
- `augur-types` - 타입 정의

**책임:**
- 핵심 비즈니스 로직 구현
- 각 모듈의 협업 조정
- 에이전트와 스킬 관리
- 조직 협업 기능 제공

#### 3. 프로토콜층(Skynet 프로토콜)

프로토콜층은 하위 레벨의 통신 및 데이터 상호작용 프로토콜을 제공하며, 전체 시스템의 기반 인프라입니다.

**주요 프로토콜:**
- `skynet-types` - 기본 타입 정의
- `skynet-auth` - 인증 프로토콜
- `skynet-chat` - 채팅 프로토콜
- `skynet-gateway` - 게이트웨이 프로토콜
- `skynet-memory` - 스토리지 프로토콜
- `skynet-service` - 서비스 프로토콜
- `skynet-bridge` - 브릿지 프로토콜
- `skynet-notification` - 알림 프로토콜
- `skynet-persistence` - 영속화 프로토콜

**책임:**
- 표준화된 통신 프로토콜 제공
- 신원 인증과 보안 처리
- 데이터 스토리지와 전송 관리
- 탈중앙화 통신 지원

## Skynet과의 관계

Skynet 프로토콜은 AI Company 시스템의 기반 인프라층(프로토콜층)을 구성합니다. 이 디렉토리는 AI Company의 **설계 철학과 아키텍처 원칙**을 설명하며, [Skynet 프로토콜](../skynet/index.md)은 이러한 설계 철학의 **구체적인 기술 구현**입니다.

### 3층 아키텍처에서의 Skynet 위치

3층 아키텍처에서 Skynet 프로토콜은 가장 하위 레벨의 기반 인프라입니다:

```
표현층(애플리케이션단)
    ↓ 호출
구현층(augur-* 핵심 모듈)
    ↓ 사용
프로토콜층(Skynet 프로토콜)← 여기가 Skynet의 위치
```

### 전체 관계도

```
AI Company 핵심 개념(concepts/)
    ↓ 기반으로 함
3층 아키텍처 구현(표현층 + 구현층)
    ↓ 기반으로 함
Skynet 프로토콜(프로토콜층)
    ↓ 따름
탈중앙화 설계 철학(architecture/)
```

### AI Company 개념과 Skynet 개념 매핑

AI Company의 핵심 개념은 Skynet 프로토콜 위에 구축됩니다:

| AI Company 개념 | Skynet 대응 개념 | 설명 |
|----------------|-----------------|------|
| **조직(Organization)** | **서브넷(Subnet)** | 각 조직은 독립적인 서브넷에 해당 |
| **사용자(실제 인간 사용자)** | **서브넷 사용자(user_id/auth_id)** | 실제 사용자는 서브넷 내의 사용자 신분에 해당 |
| **주소록 - 내부 연락처** | **user_id** | 내부 연락처는 user_id만 필요 |
| **주소록 - 외부 연락처** | **subnet_id + user_id** | 외부 연락처는 subnet_id + user_id 이중 튜플 필요 |
| **조직 구조** | **AI Company 독자적** | 조직 구조는 AI Company가 서브넷 위에 구축한 개념 |
| **팀(Agent Cluster)** | **AI Company 독자적** | 팀은 AI Company 독자적인 에이전트 협업 단위 개념 |
| **프로젝트(Project)** | **AI Company 독자적** | 프로젝트는 하나의 채널(변경 불가)과 하나의 팀(변경 가능)에 바인딩되며, 프로젝트 관리자 개념이 있음 |
| **채널(Channel)** | **채널(Channel)** | 채널은 Skynet 기본 채팅 그룹 개념으로, 프로젝트와 바인딩 후 변경 불가 |
| **태스크(Task)** | **AI Company 독자적** | 태스크는 프로젝트 하의 작업 단위 개념 |
| **직원(AI Agent)** | **AI Company 독자적** | AI Agent 직원은 스킬 집합의 컨테이너 개념 |
| **스킬(Skill)** | **AI Company 독자적** | 스킬은 Agent의 내재적 작업 능력 단위 |
| **능력(Capability)** | **AI Company 독자적** | 능력은 Agent의 외부 확장 기능(API, MCP 등 포함) |
| **워크스페이스(Workspace)** | **AI Company 독자적** | 워크스페이스는 AI Company 독자적인 분산 협업 개념 |
| **워커 노드(Worker Node)** | **서비스 노드(Service Node)** | 워커 노드는 Skynet의 서비스 노드 |
| **워크플로우(Workflow)** | **AI Company 독자적** | 워크플로우는 AI Company 독자적인 태스크 오케스트레이션 개념 |
| **일정/정기 태스크(Schedule)** | **AI Company 독자적** | 일정/정기 태스크는 AI Company 독자적인 시간 기반 태스크 개념 |
| **업무 보고서(Report)** | **AI Company 독자적** | 업무 보고서(일일 보고서, 주간 보고서, 월간 보고서)는 AI Agent, 팀, 태스크의 작업 성과 요약 개념 |

### 설계 철학과 기술 구현 대응

| 설계 철학 | Skynet 구현 |
|---------|-----------|
| 제로 트러스트 아키텍처 | 노드 신원 인증, 종단 간 암호화 |
| 탈중앙화 | 피어 투 피어 네트워크, 메인넷-서브넷 2단계 구조 |
| 검증 가능한 계산 | 디지털 서명, 다중 노드 교차 검증 |
| 데이터 주권 | 종단 간 암호화, 사용자 제어 키 |

자세한 기술 구현은 [Skynet 프로토콜](../skynet/index.md)을 참조하고, AI Company의 상위 개념은 [핵심 개념](../../concepts/index.md)을 참조하세요.
