# 구현 레이어 (augur-* 핵심 모듈)

이 문서는 AI Company 시스템에서 구현 레이어의 각 핵심 모듈을 자세히 설명합니다. 구현 레이어는 표현 레이어와 프로토콜 레이어 사이에 위치하며 핵심 비즈니스 로직과 기능 구현을 제공합니다.

## 개요

구현 레이어는 여러 개의 독립적인 `augur-*` 모듈로 구성되어 있으며 각 모듈은 특정 기능 영역을 담당합니다. 이러한 모듈은 의존성 주입과 명확한 인터페이스 설계를 통해 협업하며 상위 애플리케이션에 견고한 기능 기반을 제공합니다.

## 모듈 목록

구현 레이어에는 다음 핵심 모듈이 포함됩니다:

| 모듈 이름 | 책임 | 상태 |
|---------|------|------|
| [augur-agent](#augur-agent) | 에이전트 관리 | 핵심 |
| [augur-orchestrator](#augur-orchestrator) | 태스크 오케스트레이션 및 워크플로우 관리 | 핵심 |
| [augur-organization](#augur-organization) | 조직, 부서, 역할 관리 | 핵심 |
| [augur-skill](#augur-skill) | 스킬 플러그인 및 역량 확장 | 핵심 |
| [augur-memory](#augur-memory) | 메모리 시스템 관리 | 핵심 |
| [augur-persistence](#augur-persistence) | 영속화 레이어 구현 | 인프라스트럭처 |
| [augur-file-system](#augur-file-system) | 파일 스토리지 서비스 | 인프라스트럭처 |
| [augur-types](#augur-types) | 타입 정의 및 오류 처리 | 인프라스트럭처 |

## 모듈 상세 설명

### augur-types

**책임:** 구현 레이어의 공유 타입 정의와 통합된 오류 처리 메커니즘을 제공합니다.

**주요 기능:**
- 핵심 데이터 구조 정의 (워크스페이스, 프로젝트, 회사, 팀, 직원, 스킬 등)
- 통합 오류 타입 `AugurError` 및 오류 처리 메커니즘
- 표준 열거 타입 제공 (예: `ProjectStatus`、`RoleType`、`SkillLevel` 등)
- 국제화된 오류 메시지 지원 (i18n 키를 통해)

**핵심 구조체:**
- `Workspace` - 워크스페이스
- `Project` - 프로젝트
- `Company` - 회사
- `Team` - 팀
- `Employee` - 직원
- `Skill` - 스킬

**의존성 관계:** 다른 augur-* 모듈 의존이 없으며 모든 다른 모듈의 기반입니다.

### augur-persistence

**책임:** 통합된 영속화 레이어 구현을 제공하며 여러 데이터베이스 백엔드를 지원합니다.

**주요 기능:**
- 다중 데이터베이스 지원 (SQLite、PostgreSQL)
- 통합된 Repository 인터페이스 설계
- 데이터베이스 마이그레이션 관리
- 엔티티 타입 영속화 지원

**지원되는 엔티티 타입:**
- 사용자
- 조직
- 부서
- 역할
- 대화
- 메시지
- 에이전트
- 메모리
- 메모리 태그

**사용 예시:**
```rust
use augur_persistence::{AugurPersistence, PersistenceConfig, DatabaseType};

let config = PersistenceConfig::default();
let persistence = AugurPersistence::new(config).await?;

let user_repo = persistence.user_repository();
```

**의존성 관계:** `augur-types`에 의존하며 비즈니스 로직 모듈에서 의존합니다.

### augur-file-system

**책임:** 로컬 파일 시스템 기반의 파일 스토리지 서비스를 제공합니다.

**주요 기능:**
- 파일 업로드 및 다운로드
- 파일 메타데이터 관리
- 파일 액세스 레벨 제어
- 파일 검색 및 필터링
- 사용자 및 조직 파일 목록
- 파일 복사 및 이동 작업
- 다양한 MIME 타입 감지 지원

**사용 예시:**
```rust
use augur_file_system::{FsFileService, FsFileServiceConfig};

let config = FsFileServiceConfig::default();
let service = FsFileService::new(config).await?;
```

**의존성 관계:** `augur-types`에 의존하며 비즈니스 로직 모듈에서 의존합니다.

### augur-memory

**책임:** 메모리 시스템을 구현하며 메모리의 생성, 저장, 검색 및 관리를 지원합니다.

**주요 기능:**
- 메모리 CRUD 작업
- 메모리 태그 관리
- 메모리 관계 관리
- 키워드 검색
- 태그 및 시간 범위 필터링
- 메모리 가져오기 및 내보내기
- 대화 컨텍스트 추출
- 대화에서 메모리 생성

**사용 예시:**
```rust
use augur_memory::AugurMemory;
use std::sync::Arc;

let memory_service = AugurMemory::new(
    Arc::new(memory_repository),
    Arc::new(memory_tag_repository),
);
```

**의존성 관계:** `augur-types`、`augur-persistence`에 의존하며 `augur-agent` 등에서 의존합니다.

### augur-agent

**책임:** 에이전트(Agent) 관련 타입 정의와 인터페이스를 제공하며 에이전트의 라이프사이클을 관리합니다.

**주요 기능:**
- 에이전트 타입 정의
- 에이전트 상태 관리
- 에이전트 구성 인터페이스
- 에이전트 라이프사이클 관리

**의존성 관계:** `augur-types`、`augur-memory`、`augur-skill`에 의존하며 상위 애플리케이션에서 의존합니다.

### augur-orchestrator

**책임:** 태스크 오케스트레이션과 워크플로우 관리의 타입과 인터페이스를 제공합니다.

**주요 기능:**
- 태스크 오케스트레이션 인터페이스
- 워크플로우 관리
- 태스크 스케줄링
- 의존성 관리

**의존성 관계:** `augur-types`에 의존하며 상위 애플리케이션에서 의존합니다.

### augur-organization

**책임:** 조직, 부서 및 역할 관리의 타입과 인터페이스를 제공합니다.

**주요 기능:**
- 조직 관리
- 부서 구조
- 역할 권한
- 멤버 관리

**의존성 관계:** `augur-types`、`augur-persistence`에 의존하며 상위 애플리케이션에서 의존합니다.

### augur-skill

**책임:** 스킬 플러그인과 역량 확장의 타입과 인터페이스를 제공합니다.

**주요 기능:**
- 스킬 플러그인 인터페이스
- 스킬 정의
- 스킬 실행
- 플러그인 관리

**의존성 관계:** `augur-types`에 의존하며 `augur-agent`에서 의존합니다.

## 모듈 간 협업 예시

### 예시 1: 에이전트 태스크 실행

1. 상위 애플리케이션이 `augur-orchestrator`를 호출하여 태스크를 시작합니다
2. `augur-orchestrator`가 사용 가능한 `augur-agent` 에이전트를 찾습니다
3. `augur-agent`가 `augur-skill`을 사용하여 필요한 스킬을 로드합니다
4. 실행 과정에서 `augur-agent`가 `augur-memory`를 사용하여 메모리를 기록하고 검색합니다
5. 모든 상태 변경은 `augur-persistence`를 통해 영속화됩니다

### 예시 2: 조직 협업

1. 상위 애플리케이션이 `augur-organization`을 통해 조직 아키텍처를 관리합니다
2. `augur-organization`이 `augur-persistence`를 사용하여 조직 데이터를 저장합니다
3. 사용자 파일 업로드는 `augur-file-system`을 통해 관리합니다
4. 조직 내의 에이전트는 `augur-agent`를 통해 협업합니다

## 설계 원칙

구현 레이어는 다음 설계 원칙을 따릅니다:

1. **단일 책임 원칙** - 각 모듈은 하나의 명확한 기능 영역만 담당합니다
2. **의존성 역전 원칙** - 상위 모듈은 하위 모듈에 의존하지 않고 모두 추상화에 의존합니다
3. **인터페이스 분리 원칙** - 최소화된 인터페이스를 제공하며 비대한 인터페이스를 피합니다
4. **모듈화 설계** - 모듈 간 명확한 경계와 의존성 관계를 통해 협업합니다
5. **테스트 가능성** - 각 모듈은 독립적으로 쉽게 테스트할 수 있어야 합니다

## 확장 가이드

새 기능을 추가해야 할 때 다음 단계를 따르세요:

1. 기능이 기존 모듈 중 어느 모듈에 속하는지 또는 새 모듈을 생성해야 하는지 결정합니다
2. `augur-types`에서 필요한 데이터 구조와 오류 타입을 정의합니다
3. 해당 비즈니스 모듈에서 핵심 로직을 구현합니다
4. 영속화가 필요한 경우 `augur-persistence`에 Repository를 추가합니다
5. 파일 스토리지가 필요한 경우 `augur-file-system`을 사용합니다
6. 이 문서를 업데이트하여 새 기능의 설명을 기록합니다
