# 기술 선택

## 개요

이 문서는 AI Company 시스템의 기술 선택 결정을 기록하며, 통신 프로토콜, 발견 메커니즘, 보안 표준 등을 포함합니다.

## 노드 간 통신

### 발견 메커니즘

시스템은 다계층 노드 발견 메커니즘을 채택합니다:

| 발견 방식 | 기술 선택 | 용도 |
|---------|---------|------|
| **로컬 네트워크 발견** | mDNS/Bonjour | 로컬 네트워크 노드 자동 발견 |
| **클라우드 발견** | 클라우드 디렉토리 서비스 | 원격 노드 발견 |
| **수동 연결** | 직접 주소 입력 | 수동으로 노드 연결 지정 |

### 통신 프로토콜

| 프로토콜 유형 | 기술 선택 | 용도 |
|-----------|---------|------|
| **실시간 통신** | WebSocket | 양방향 실시간 통신 |
| **서비스 호출** | gRPC | 효율적인 서비스 간 호출 |
| **파일 동기화** | rsync 또는 유사 프로토콜 | 증분 파일 동기화 |

### 보안 통신

| 보안 메커니즘 | 기술 선택 | 설명 |
|-----------|---------|------|
| **전송 암호화** | TLS 1.3 | 모든 통신 암호화 |
| **노드 인증** | 노드 인증서 | 양방향 인증 |
| **데이터 암호화** | 종단 간 암호화 | 민감한 데이터 종단 간 암호화 |

## 작업 노드 관련 기술

### 노드 유형 지원

시스템은 다음 작업 노드 유형을 지원합니다:
- Windows 개인 PC
- 서버
- Android 휴대폰
- iOS 휴대폰
- 태블릿 장치
- IoT 장치

### 노드 상태

| 상태 | 설명 |
|------|------|
| **Online** | 노드가 온라인이고 유휴 상태 |
| **Busy** | 노드가 온라인이지만 바쁨 |
| **Offline** | 노드가 오프라인 |
| **Maintenance** | 노드가 유지 관리 중 |

## 스토리지 기술 선택

자세한 스토리지 아키텍처와 기술 선택은 [data-models.md](./data-models.md)를 참조하세요.

### 데이터베이스 선택

| 데이터베이스 | 용도 | 시나리오 |
|---------|------|------|
| **SQLite** | 경량형 관계형 데이터베이스 | 단일 서버 배포 |
| **PostgreSQL** | 기업급 관계형 데이터베이스 | 프로덕션 환경 |

### 객체 스토리지 선택

| 스토리지 유형 | 용도 | 시나리오 |
|-----------|------|------|
| **파일 시스템 (FS)** | 로컬 파일 스토리지 | 단일 서버 배포 |
| **S3** | 객체 스토리지 서비스 | 프로덕션 환경과 클라우드 배포 |

## 기술 선택 원칙

1. **오픈 소스 우선**: 성숙한 오픈 소스 기술을 우선 선택
2. **표준화**: 산업 표준과 모범 사례 따름
3. **확장 가능**: 수평 확장을 지원하는 기술 선택
4. **보안성**: 보안성과 개인정보 보호를 우선 고려
5. **성능**: 기술 선택이 성능 요구 사항을 만족하도록 함
