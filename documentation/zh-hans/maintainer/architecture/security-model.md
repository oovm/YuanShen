# 安全模型

本文档描述 AI Company 作为 Skynet 协议上的一种子网实现，如何在架构层面补充安全机制。

## 概述

### 分层职责划分

| 层级 | 负责内容 | 说明 |
|------|---------|------|
| **Skynet 协议层** | 网络通信、基础密码学原语、子网抽象 | 轻量化、灵活、通用 |
| **子网实现层（AI Company）** | 特定场景的安全机制、客户端实现指南 | 根据子网类型按需实现 |

Skynet 协议只定义**最小必要**的安全机制，保持轻量化和灵活性。具体子网（如 AI Company）根据自身需求在架构层补充额外的安全措施。

---

## 一、元数据保护

### Skynet 协议层定位
Skynet 协议**不提供**元数据保护，保持协议轻量化。

### AI Company 子网层负责实现

对于企业级应用，元数据保护方案由 AI Company 负责设计和实现：

#### 基线措施（推荐）
| 措施 | 说明 |
|------|------|
| **路由随机化** | 客户端随机选择服务节点 |
| **时间戳精度降低** | 秒级精度（而非毫秒） |

#### 长期规划：混合网络
如需强元数据保护，AI Company 可在未来版本引入混合网络（如 Loopix），但这需要：
- 显著的架构变更
- 接受更高的延迟和带宽开销
- 仅适用于隐私要求极高的场景

## 二、抗量子密码学（PQC）迁移

### Skynet 协议层定位
Skynet 协议**预留扩展点**，支持 PQC 算法迁移，但不强制要求。

### AI Company 子网层负责实现

#### 2.1 混合证书模式
AI Company 负责实现同时支持经典密码学和后量子密码学：
- **双密钥对**：每个身份同时持有 Ed25519 和 CRYSTALS-Dilithium 密钥对
- **双签名**：重要操作同时使用两种算法签名
- **渐进迁移**：先支持验证，再逐步切换到 PQC 为主

#### 2.2 PQC 密码套件
| 组件 | 经典算法 | PQC 算法 | 混合模式 |
|------|---------|---------|---------|
| **签名** | Ed25519 | CRYSTALS-Dilithium | Ed25519 + Dilithium |
| **密钥封装** | X25519 | CRYSTALS-Kyber | X25519 + Kyber |
| **哈希** | Blake3 | Blake3 | Blake3 |

#### 2.3 密钥轮换策略
- **紧急轮换**：发现量子威胁时可立即触发全网络密钥轮换
- **定期轮换**：默认每 90 天轮换一次长期密钥
- **前向安全**：会话密钥使用 PQC KEM 确保前向安全

### 迁移路线图
```
阶段 1（当前）：经典密码学为主
    ↓
阶段 2：混合模式（同时支持经典和 PQC）
    ↓
阶段 3：PQC 为主，经典作为备选
    ↓
阶段 4：完全 PQC（移除经典算法支持）
```

## 三、客户端安全实现指南（AI Company 子网层）

### Skynet 协议层定位
Skynet 协议**定义接口**，但将具体实现交给客户端和子网层。

### AI Company 子网层规范

#### 3.1 密钥管理规范

##### 密钥存储层级
| 密钥类型 | 存储位置 | 加密保护 |
|---------|---------|---------|
| **身份私钥** | 系统密钥链 / HSM / TEE | 硬件级保护 |
| **设备私钥** | 加密的本地存储 | 用户密码派生密钥 |
| **会话密钥** | 内存（进程隔离） | 自动销毁 |

##### 密钥派生要求
- **算法**：强制使用 Argon2id
- **参数**：
  - 内存：至少 64MB
  - 迭代次数：至少 3 次
  - 并行度：4
  - 盐值：16 字节 CSPRNG 生成

##### 密钥备份与恢复
- **Shamir 秘密分享**：将恢复密钥分成 5 份，3 份可恢复
- **离线存储**：鼓励用户将恢复密钥打印或存储在离线设备
- **社交恢复**：可选支持信任联系人协助恢复

#### 3.2 API Key 管理规范（AI Company 特定）

##### API Key 安全原则
| 原则 | 说明 |
|------|------|
| **最小权限** | 每个 API Key 只授予完成任务所需的最小权限 |
| **短暂有效** | 优先使用短期 Token，而非永久 API Key |
| **隔离使用** | 不同 Agent/服务使用不同的 API Key |
| **可撤销** | 随时可撤销泄露或不再需要的 API Key |

##### API Key 存储
- **存储位置**：系统密钥链 / 安全密钥管理服务（KMS）
- **加密保护**：静态加密，使用主密钥加密 API Key
- **内存保护**：使用后立即从内存清除，避免交换到磁盘

##### API Key 生命周期管理
```
创建 → 分发 → 使用 → 轮换 → 撤销 → 销毁
```

**创建**：
- 使用 CSPRNG 生成足够强度的 API Key（至少 256 位熵）
- 记录创建时间、创建者、用途、权限范围

**分发**：
- 安全信道传输（端到端加密）
- 避免在日志、错误信息中暴露完整 API Key
- 仅显示 Key 的前/后几位用于识别

**使用**：
- 通过环境变量或安全配置文件注入，而非硬编码
- 使用请求头或授权字段传递（如 `Authorization: Bearer <key>`）
- 避免在 URL 查询参数中传递

**轮换**：
- 定期轮换（默认 90 天）
- 支持新旧 Key 共存过渡期（至少 7 天）
- 触发安全事件时立即轮换

**撤销**：
- 提供自助撤销接口
- 撤销后立即失效
- 记录撤销原因和时间

**销毁**：
- 从所有存储位置删除
- 覆盖内存和磁盘中的残留
- 验证销毁完成

##### API Key 泄露应急响应
1. **立即撤销**：发现泄露后第一时间撤销
2. **审计日志**：检查该 Key 的所有使用记录
3. **影响评估**：评估泄露可能造成的损失
4. **通知用户**：通知受影响的用户/团队
5. **根因分析**：找出泄露原因，防止再次发生
6. **安全加固**：改进存储和使用方式

##### 临时 Token 优先
对于 Agent 场景，优先使用短期 Token 而非永久 API Key：
- **OAuth 2.0**：使用 Client Credentials 或 Authorization Code Flow
- **JWT**：短期 JWT Token（有效期 < 1 小时）
- **动态刷新**：使用 Refresh Token 获取新的 Access Token

#### 3.3 随机数生成规范

##### 熵源要求
- **主要熵源**：操作系统 CSPRNG（Windows: `CryptGenRandom`, Linux: `/dev/urandom`）
- **补充熵源**：
  - 设备传感器数据（加速计、陀螺仪）
  - 用户交互时间戳
  - 网络延迟测量
- **熵混合**：使用 Fortuna 或 Yarrow 算法混合多源熵

##### CSPRNG 验证
- 实现 NIST SP 800-90A 标准
- 定期进行随机性测试（Dieharder、TestU01）
- 禁止使用任何非密码学安全的随机数生成器

#### 3.4 参考实现（AI Company 子网 SDK）
提供官方 SDK，包含：
- **加密库封装**：统一的密码学原语接口
- **密钥管理模块**：开箱即用的安全密钥存储
- **API Key 管理模块**：安全的 API Key 生命周期管理

## 四、安全审计与日志（AI Company 负责）

### Skynet 协议层定位
审计日志**不纳入 Skynet 协议**，完全由子网创建者根据需求自主实现。

### 原因
不同子网类型的审计需求差异极大：

| 子网类型 | 审计需求 | 示例 |
|---------|---------|------|
| **组织子网（AI Company）** | 高要求 | 完整审计日志、不可篡改、多年保留、合规认证 |
| **社区子网** | 中要求 | 基础操作日志、可选保留 |
| **私有子网** | 低要求 | 可能不需要任何审计日志 |

### AI Company 子网负责实现

AI Company 作为企业级子网，负责实现完整的审计日志功能：

#### 4.1 审计事件类型
- 身份认证事件
- 密钥/API Key 操作
- 权限变更
- 敏感资源访问

#### 4.2 日志安全要求
- **客户端本地存储**：审计日志由客户端收集和存储
- **加密保护**：敏感审计日志加密存储
- **完整性保护**：使用数字签名防止篡改
- **子网级配置**：子网创建者可定义审计策略

## 五、女巫攻击防护（AI Company 负责）

### Skynet 协议层定位
Skynet 协议**不强制**女巫攻击防护，保持协议灵活性。

### AI Company 子网层负责实现

#### 5.1 多层防护体系

| 防护层级 | 机制 | 说明 |
|---------|------|------|
| **第一层** | 身份验证 | 邮箱、手机号、WebAuthn 等 |
| **第二层** | 工作量证明 | Hashcash 或类似机制 |
| **第三层** | 社交图谱验证 | 信任联系人背书 |
| **第四层** | 经济抵押 | 锁定 Token 作为保证金 |

#### 5.2 身份验证选项
- **WebAuthn/FIDO2**：推荐的强认证方式
- **邮箱验证**：发送验证链接
- **手机号验证**：短信验证码
- **OAuth**：支持第三方身份提供商（Google、GitHub 等）

#### 5.3 信誉系统
- **初始信誉**：新用户低信誉，限制操作频率
- **信誉积累**：正常使用逐渐提高信誉
- **信誉惩罚**：恶意行为降低信誉
- **跨子网信誉**：信誉可在不同子网间共享

## 六、前向保密强化（子网层实现指南）

### Skynet 协议层定位
Skynet 协议**使用** Double Ratchet 和 MLS 提供前向保密，但具体实现细节由客户端负责。

### AI Company 子网层规范

#### 6.1 密钥销毁规范

##### 内存密钥销毁
- **零覆盖**：使用 memset_s 或等效函数覆盖密钥内存
- **多次覆盖**：至少 3 次不同模式覆盖
- **内存锁定**：使用 mlock/VirtualLock 防止密钥交换到磁盘

##### 持久化密钥销毁
- **安全删除**：使用 shred 或等效工具
- **SSD 处理**：针对 SSD 特殊处理（TRIM、安全擦除）
- **验证销毁**：确认密钥材料已无法恢复

#### 6.2 前向保密保证
- **会话密钥短命**：每次消息轮换密钥（Double Ratchet）
- **无密钥缓存**：不缓存任何可用于解密旧消息的密钥
- **完美前向保密（PFS）**：明确保证 PFS 属性

## 七、安全边界与纵深防御（AI Company 子网层）

### 7.1 安全边界定义

| 边界 | 保护措施 |
|------|---------|
| **客户端边界** | 沙箱隔离、进程隔离、内存保护 |
| **网络边界** | TLS 1.3、证书锁定、证书透明度 |
| **服务节点边界** | 最小权限、网络隔离、入侵检测 |
| **数据边界** | 端到端加密、静态加密、访问控制 |

### 7.2 纵深防御策略

```
第一层：客户端安全
    ↓
第二层：传输安全（TLS 1.3 + Noise）
    ↓
第三层：端到端加密（X3DH + Double Ratchet / MLS）
    ↓
第四层：多节点验证
    ↓
第五层：审计日志与异常检测（可选）
```

## 总结

### 分层职责回顾

| 层级 | 职责 |
|------|------|
| **Skynet 协议层** | 提供轻量化、灵活的基础：密码学原语、网络通信、子网抽象 |
| **AI Company 子网层** | 企业级安全实现：API Key 管理、审计日志、合规认证等 |

### 明确责任划分

| 安全领域 | Skynet 协议 | AI Company |
|---------|------------|------------|
| **元数据保护** | 不提供 | 负责实现 |
| **抗量子破解** | 预留扩展点 | 负责实现 |
| **API Key 管理** | 不涉及 | 负责 |
| **审计日志** | 不纳入 | 负责 |
| **女巫防护** | 不强制 | 负责 |

### AI Company 安全模型补充

作为 Skynet 上的企业级子网实现，AI Company 安全模型通过以下方式补充协议层：

1. **元数据保护**：AI Company 负责实现，提供基线措施和长期规划
2. **抗量子迁移**：AI Company 负责实现，混合证书模式、渐进迁移路线图
3. **客户端安全**：密钥管理规范、API Key 管理规范、随机数生成规范、官方 SDK
4. **审计日志**：AI Company 负责实现，完整审计日志功能
5. **女巫防护**：AI Company 负责实现，多层防护、身份验证、信誉系统
6. **前向保密**：密钥销毁规范、PFS 保证
7. **合规认证**：GDPR、SOC 2、ISO 27001

二者结合，构成完整的企业级安全体系，同时保持 Skynet 协议本身的轻量化和灵活性。
