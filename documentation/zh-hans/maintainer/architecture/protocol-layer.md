# 协议层设计

本文档详细说明 AI Company 系统的协议层，即 protocols/ 目录下的 Skynet 协议模块。协议层是整个系统的基础设施，提供标准化的通信协议、数据类型定义和交互接口。

## 协议层概述

协议层是 AI Company 三层架构中的最底层，为上层实现层（augur-* 核心模块）和表现层提供基础服务和标准化交互协议。

### 协议层在架构中的作用

### 核心职责

协议层的核心职责包括：

1. **提供标准化的数据类型定义**：统一各模块间的数据交换格式
2. **定义通信协议**：规范模块间、服务间的交互方式
3. **提供基础安全机制**：身份认证、加密传输、权限控制
4. **支持去中心化通信**：主网-子网两级结构，对等网络通信
5. **抽象底层差异**：为上层提供统一的接口，屏蔽底层实现细节

## 协议模块详解

### 1. skynet-types - 基础类型定义

**职责与功能**：
- 提供 Skynet 协议层的所有共享类型定义
- 定义核心数据结构、枚举和常量
- 提供身份标识生成和处理机制
- 定义错误类型和统一的错误处理规范
- 提供 JSON-RPC 和 WebSocket 消息类型

**主要子模块**：
- `agent` - 智能体相关类型
- `bridge` - 桥接相关类型
- `chat` - 聊天相关类型
- `error` - 错误相关类型
- `id` - 身份标识相关类型
- `jsonrpc` - JSON-RPC 相关类型
- `memory` - 记忆相关类型
- `org` - 组织相关类型
- `resource` - 资源相关类型
- `subnet` - 子网相关类型
- `user` - 用户相关类型
- `utils` - 工具函数
- `websocket` - WebSocket 相关类型

**在架构中的作用**：作为所有其他协议模块的基础，提供统一的类型系统，确保各模块间的数据兼容性。

---

### 2. skynet-auth - 认证协议

**职责与功能**：
- 提供用户身份认证接口
- 管理权限和访问控制
- 处理会话管理和令牌
- 支持多种认证方式

**核心功能**：
- 用户认证流程定义
- 权限管理和授权机制
- 会话令牌生成和验证
- Token 生命周期管理

**在架构中的作用**：为整个系统提供安全的身份认证和权限控制基础，确保只有授权的用户和服务才能访问系统资源。

---

### 3. skynet-chat - 聊天协议

**职责与功能**：
- 提供实时聊天和会话管理
- 定义消息类型和格式
- 支持聊天历史记录
- 提供实时通信接口

**核心功能**：
- 会话（频道）管理
- 多种消息类型定义（文本、文件、图片等）
- 实时消息推送
- 聊天历史查询和检索

**在架构中的作用**：为 AI Company 的协作功能提供基础通信支持，包括项目频道、团队沟通等。

---

### 4. skynet-gateway - 网关协议

**职责与功能**：
- 提供 API 网关接口
- 处理请求路由和转发
- 实现负载均衡
- 执行安全验证

**核心功能**：
- 请求路由和分发
- 服务发现和负载均衡
- 请求验证和安全过滤
- API 版本管理

**在架构中的作用**：作为系统的入口点，统一管理外部请求，提供安全、高效的 API 访问通道。

---

### 5. skynet-memory - 记忆协议

**职责与功能**：
- 提供记忆存储和检索接口
- 定义记忆数据类型
- 支持记忆搜索和查询
- 管理记忆标签和分类

**核心功能**：
- 记忆数据的存储和读取
- 记忆向量搜索
- 标签管理和分类
- 记忆关联和上下文

**在架构中的作用**：为智能体提供记忆系统支持，使智能体能够记住历史交互、学习经验并形成长期记忆。

---

### 6. skynet-service - 服务协议

**职责与功能**：
- 提供通用服务接口定义
- 支持服务发现机制
- 实现健康检查和监控
- 管理服务注册和注销

**核心功能**：
- 统一的服务接口规范
- 服务注册与发现
- 健康状态监控
- 服务生命周期管理

**在架构中的作用**：为系统中的各类服务提供统一的注册、发现和通信机制，支持微服务架构。

**职责与功能**：
- 提供外部系统集成接口

**在架构中的作用**：使 AI Company 能够与外部系统（如第三方服务、遗留系统等）进行集成和通信。

**职责与功能**：

**在架构中的作用**：为系统提供统一的文件和对象存储抽象，支持各种存储需求。

## 协议层设计原则

### 1. 轻量化与灵活性

协议层只定义**最小必要**的接口和类型，保持轻量化和灵活性。具体实现细节由上层模块根据需求自主实现。

### 2. 标准化与一致性

所有协议模块遵循统一的设计规范和命名约定，确保各模块间的一致性和互操作性。

### 3. 可扩展性

协议设计预留扩展点，支持未来功能的添加和升级，而无需破坏现有接口。

### 4. 安全性优先

协议层内置基础安全机制，包括身份认证、加密传输、权限控制等，确保系统安全性。

### 5. 去中心化支持

协议层支持主网-子网两级结构，对等网络通信，为去中心化应用提供基础设施。

## 与上层的交互关系

### 实现层（augur-* 模块）

实现层的核心模块（如 augur-agent、augur-orchestrator 等）直接使用协议层提供的接口和类型：

- `augur-agent` 使用 `skynet-types` 和 `skynet-memory`
- `augur-organization` 使用 `skynet-types` 和 `skynet-persistence`
- `augur-orchestrator` 使用 `skynet-service` 和 `skynet-gateway`

### 表现层（应用端）

表现层通过实现层间接使用协议层，或在某些情况下直接使用协议层的基础类型和接口。

## 总结

协议层是 AI Company 系统的基础设施，通过提供标准化的通信协议、数据类型定义和交互接口，为上层实现层和表现层提供坚实的基础。各协议模块各司其职，共同构成一个完整、灵活、安全的协议体系，支持系统的去中心化设计和企业级应用需求。

通过协议层的抽象，AI Company 实现了：
- 模块化设计，各部分可独立演进
- 标准化接口，便于集成和扩展
- 安全基础，保障系统安全性
- 去中心化支持，实现数据主权和用户控制
