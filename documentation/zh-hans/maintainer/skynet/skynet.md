# Skynet 协议设计草案

## 1. 概述
Skynet 是一个去中心化通信协议，旨在构建安全、隐私保护的即时通讯网络。其核心架构由**服务节点**组成一个对等网络，维护**主网**与**子网**两级结构。客户端可连接任意服务节点，并通过端到端加密实现设备间安全通信。协议设计遵循**零信任**原则：服务节点之间、服务节点与客户端之间均假设对方可能恶意，所有关键数据必须经密码学验证。

### 2. 节点身份与网络发现
- **节点标识**：每个服务节点拥有一个长期 Ed25519 密钥对，节点 ID 为公钥的哈希值（`NodeID = blake3(public_key)`）。节点间通信使用 Noise 协议（XX 模式）建立加密通道，并相互验证 NodeID。
- **网络发现**：
  - 初始节点通过预配置的种子节点列表加入网络。
  - 节点维护一个 Kademlia 风格的分布式哈希表（DHT），用于存储其他节点的地址信息（IPv4/IPv6 + port）和活性探测。
  - 节点定期向 DHT 发布自己的地址，并刷新邻居列表。
  - 每个节点需支持 STUN 协议辅助 NAT 穿透；无法穿透时，可通过其他节点中继（TURN-like 功能，但中继节点仅转发加密数据）。

### 4. 用户身份与认证
- **全局身份**：每个用户拥有一个全局 UUID `auth_id`，以及一个长期 Ed25519 密钥对（用于身份签名）。用户首次使用时生成该身份，公钥由用户自己签名发布。**auth_id 是 Skynet 协议的最高机密，绝不应在子网内部数据中泄露或存储。**
- **子网模型**：
  - 每个独立的通信系统或社区都是一个独立的子网
  - 用户在不同子网中有不同的联系人列表
  - `auth_id` 类似真名，跨子网唯一标识用户，**仅用于用户身份认证，不在子网内部数据中使用**
  - `user_id` 类似昵称/网名，子网内本地标识，用于隐私保护，**子网内部所有数据只使用 user_id**
  - 用户在子网内只使用 `user_id` 作为标识
  - 用户在子网内的公钥（可使用全局身份公钥，也可单独生成子网专用密钥）需经自己签名后提交给子网维护节点
  - 用户可同时加入多个子网，使用同一个 `auth_id` 进行认证
  - **子网类型**：每个子网有类型标识（如 `organization`、`community`、`private`、`custom`），客户端根据类型决定是否加载和如何处理
  - **子网元信息**：每个子网包含元信息（类型、版本、名称、描述、功能特性等），用于客户端识别和适配
- **客户端认证**：
  - 客户端连接服务节点时，需提供 `auth_id` 并完成挑战-响应：服务节点发送随机数，客户端用身份私钥签名后返回，服务节点验证签名。
  - 认证通过后，服务节点为该客户端生成一个临时会话密钥（用于后续请求加密），并在会话有效期内维护客户端的在线状态。

### 5. 端到端加密
所有用户间通信内容（私聊、群聊消息、文件传输）均采用端到端加密，服务节点无法解密。加密方案借鉴 Signal 协议和 MLS 协议：
- **设备密钥**：每个客户端设备生成一个 X25519 密钥对作为设备标识，并用用户身份私钥签名后发布到其所加入的子网中（作为成员列表的一部分）。用户可拥有多个设备。
- **私聊**：
  - 双方通过 X3DH 密钥交换协议建立共享密钥，并使用双棘轮算法（Double Ratchet）生成会话密钥，实现前向安全与后向安全。
  - 初始密钥交换消息可通过服务节点转发（加密），服务节点仅传递密文。
- **群聊**：
  - 采用 MLS（Messaging Layer Security）协议，提供前向保密、后向保密和成员变化时的高效密钥轮换。
  - MLS 协议自动处理成员加入/离开时的密钥更新，无需管理员手动干预。
- **元数据保护**：
  - 服务节点只能看到消息的接收者（目标子网和用户/群组），但无法看到消息内容。为隐藏接收者，可考虑使用混合网络（如 Loopix）技术，但初始版本暂不实现，留给后续扩展。

### 5.1 安全参数（效率优先）
Skynet 协议采用以下安全参数，在保证企业级安全性的前提下优先考虑性能和用户体验：
| 参数 | 取值 | 说明 |
|------|------|------|
| **签名算法** | Ed25519 | 节点和用户身份签名 |
| **密钥交换** | X25519 | X3DH 和 MLS 使用 |
| **哈希算法** | Blake3-256 | 256 位输出，用于 NodeID、content_hash 等 |
| **对称加密** | ChaCha20-Poly1305 | 消息加密，256 位密钥 |
| **Noise 协议** | Noise_XX_25519_ChaChaPoly_BLAKE2s | 节点间通信 |
| **X3DH 预密钥数** | 100 | 预生成的一次性预密钥数量 |
| **MLS 密码套件** | MLS10_128_HPKEX25519_AES128GCM_SHA256_Ed25519 | MLS 协议密码套件 |

### 5.2 设计原则
Skynet 协议遵循以下核心设计原则：
1. **效率优先**：在保证基本安全性的前提下，优先考虑系统性能和用户体验
2. **现代化方案**：采用经过充分验证的现代密码学原语和协议
3. **可扩展设计**：架构设计支持未来安全机制的平滑扩展
4. **实用安全**：提供企业级安全保障，不追求军规级过度设计

### 5.3 重放攻击防护
所有加密消息都包含防重放机制：
- **消息序号**：每个消息包含单调递增的 64 位无符号整数序号
- **重放窗口**：接收方维护最近 1000 个消息序号的滑动窗口
- **验证逻辑**：
  1. 如果序号 ≤ 窗口最小值，丢弃
  2. 如果序号在窗口内且已存在，丢弃
  3. 否则接受消息并更新窗口
- **服务端防护**：维护节点同样验证序号，防止恶意客户端重放消息

### 6. 数据存储与同步
子网数据由一组维护节点共同存储，需保证在部分节点恶意情况下的可靠性与一致性。
- **数据模型**：
  - 所有子网数据以**不可变操作日志**的形式存储，每个操作（如添加成员、创建资源、发送消息）由发起者签名，包含单调递增的序列号。
  - 日志最终收敛为确定性的状态（可通过重放操作重建）。
  - **资源数据**：包括文件、图片等资源的元数据和内容哈希，资源内容可存储在分布式存储（如 IPFS）或本地存储中。
  - **消息数据**：包括消息内容、发送者、接收者、时间戳等，支持端到端加密。
- **复制协议**：
  - 维护节点之间通过 Gossip 协议交换操作日志，每个节点独立验证签名和权限。
  - 使用**向量时钟**或**版本向量**检测冲突，冲突解决规则由子网策略定义（如“管理员操作优先”或“时间戳优先”）。
  - 节点定期对日志进行哈希快照，并与其他节点比对，若发现不一致（如节点恶意篡改历史），其他节点可将其标记为不可信并触发管理员介入。
- **写操作**：
  - 客户端提交写操作（如邀请成员）到任一服务节点，该节点将请求转发给所有维护节点。
  - 维护节点验证权限和签名后，将操作追加到本地日志，并广播给其他维护节点。
  - 客户端可要求多数维护节点确认后认为操作成功，或采用“写后读”验证：从多个维护节点读取最新状态，若不一致则报警。
- **读操作**：
  - 客户端可从任意维护节点读取子网数据，但需从多个节点获取并比较，采用多数一致的结果；或只信任由足够多节点签名的数据（如合并签名）。
  - 为提高性能，客户端可缓存数据并定期轮询更新。

### 7. 消息传递流程
以用户 A 向用户 B 发送私聊消息为例：
1. A 的客户端连接至某服务节点 S（可任意选择）。
2. 客户端向 S 发起请求：获取 B 在目标子网内的设备公钥列表。S 从该子网的维护节点中获取并返回（需多个节点比对，或信任由 B 签名的公钥包）。
3. A 使用 B 的公钥执行 X3DH 握手，生成会话密钥，并加密消息内容。
4. A 将加密后的消息包（包含接收者标识：subnet_id、B 的 user_id）发送给 S。
   - **子网隔离原则**：消息仅在同一子网内传递，不跨子网路由。
5. S 根据 subnet_id 找到该子网的维护节点集合，并将消息转发给这些节点（或选择一个节点存储离线消息）。
6. 若 B 在线，其连接的某个服务节点会通过 Gossip 或订阅机制收到消息，并推送给 B；若 B 离线，维护节点存储消息，等待 B 上线后拉取。
7. B 收到密文后，使用自己的设备私钥解密，并发送确认回执（可选）。

群聊消息类似，但使用群组对称密钥加密，接收者为 channel_id，由维护节点将消息分发给群内所有在线成员（或存储为群聊历史）。

**跨子网转发**：如需将消息转发到其他子网，必须在目标子网中复制该消息，而非直接引用。复制后，目标子网中的消息拥有独立的生命周期。

### 8. 安全考虑与恶意假设应对
- **服务节点恶意**：
  - **篡改数据**：所有重要数据（成员列表、公钥）均有发起者签名，客户端可验证签名，且从多个节点获取交叉对比。
  - **拒绝服务**：客户端可切换连接的其他服务节点；子网维护节点若集体作恶，客户端可通过社交渠道发现并重建子网。
  - **窃听元数据**：端到端加密保护内容，但服务节点仍能看到通信关系（谁在跟谁聊）。后续可引入 Mix 网络隐藏关系。
- **客户端恶意**：
  - **滥用资源**：服务节点对每个客户端实施速率限制，可要求客户端进行基于难度的工作量证明（如 Hashcash）或支付微额通证（若引入经济模型）。
  - **假冒身份**：所有客户端操作需用身份私钥签名，服务节点验证签名，防止伪造。
  - **女巫攻击**：加入子网需管理员审核，可防止攻击者创建大量虚假身份；全局身份注册可考虑结合外部锚点（如电子邮件验证）但非强制。
- **子网维护节点共谋**：
  - 若子网中超过半数的维护节点恶意，可篡改数据或拒绝服务。为此，子网创建者可选择维护节点时要求其提供抵押（如锁定 Token），或在协议层面允许客户端从可信第三方获取数据（如社交图谱验证）。设计上可引入“见证节点”机制，允许普通节点订阅子网数据并生成一致性证明，客户端可依赖这些见证节点。

### 9. 客户端与服务端交互概览（参考）
客户端功能参考 IM 产品，主要交互包括：
- **登录**：提供 `auth_id` 和签名挑战，获取会话令牌。
- **子网切换**：客户端列出用户已加入的子网（本地缓存），切换后 UI 显示对应上下文。
- **联系人**：从子网数据中获取用户列表，支持搜索。
- **发送消息**：端到端加密后发送至服务节点，服务节点路由到目标子网维护节点。
- **接收消息**：通过长轮询或 WebSocket 从服务节点接收推送。
- **群管理**：创建群、邀请成员、修改群信息，操作需签名并提交至子网维护节点。
- **资源管理**：上传、下载、更新、删除资源，资源内容哈希存储在子网数据中，内容可存储在分布式存储（如 IPFS 或类似）。
- **文件传输**：文件作为资源上传，然后将资源引用作为消息发送。

### 10. 协议边界与免责声明

Skynet 协议明确定义了以下**不涉及、不负责**的内容：

| 类别 | 说明 | 责任方 |
|------|------|--------|
| **密钥管理** | 用户身份私钥、设备密钥的存储、备份、恢复 | 客户端 |
| **随机数生成** | CSPRNG（密码学安全伪随机数生成器）的实现和熵源 | 客户端 |
| **密钥派生** | 从密码/口令派生密钥的算法（如 PBKDF2、Argon2） | 客户端 |
| **硬件安全模块** | HSM、安全元件（SE）、可信执行环境（TEE）的使用 | 客户端 |
| **生物识别认证** | 指纹、面部识别等生物识别方式 | 客户端 |
| **抗量子密码学** | 后量子密码学（PQC）迁移和密钥封装机制 | 超纲，暂不涉及 |
| **混合网络** | Loopix 等元数据隐藏技术 | 可选扩展，初始版本不实现 |
| **经济激励** | Token、抵押、工作量证明等经济模型 | 可选扩展 |
| **治理机制** | DAO、投票、仲裁等去中心化治理 | 可选扩展 |

**重要说明**：
- Skynet 协议仅定义网络通信和数据结构规范
- 客户端实现者需自行确保上述安全机制的正确实现
- 密码学安全最终依赖于客户端的正确实现和用户的安全意识

### 10. 总结
Skynet 协议通过去中心化服务节点网络、子网隔离、端到端加密和拜占庭容错数据复制，为构建类似企业 IM 的隐私保护通信系统提供了基础。协议设计充分考虑了服务端与客户端互相不信任的场景，确保用户数据所有权和控制权掌握在自己手中。

#### 安全定位
Skynet 协议的安全目标是**企业级实用安全**，而非军规级过度设计：
- ✅ 保护企业通信隐私和数据安全
- ✅ 抵御常见网络攻击和内部威胁
- ✅ 提供良好的性能和用户体验
- ❌ 不追求对抗国家级对手的极端安全
- ❌ 不牺牲可用性换取理论上的绝对安全

#### 未来扩展方向
协议设计为未来安全升级预留了扩展空间：
1. **元数据保护**：可引入混合网络技术隐藏通信关系
2. **后量子迁移**：支持平滑过渡到后量子密码学算法
3. **共识增强**：可根据需求升级共识算法和安全阈值
4. **审计增强**：可扩展更细粒度的安全审计和合规功能
