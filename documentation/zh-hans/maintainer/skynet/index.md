# Skynet 协议

Skynet 是 AI Company 的去中心化通信协议，基于零信任架构设计，实现安全、隐私保护的即时通讯网络。

## 协议范围

Skynet 协议**负责**：
- 节点身份认证和网络发现
- 端到端加密通信（X3DH + Double Ratchet 私聊，MLS 群聊）
- 子网数据存储和同步（拜占庭容错复制）
- 消息、资源、用户元信息的数据结构定义

Skynet 协议**不负责**：
- 密钥管理（存储、备份、恢复）- 由客户端负责
- 随机数生成和熵源 - 由客户端负责
- 抗量子密码学 - 超纲，暂不涉及
- 硬件安全模块、生物识别等客户端安全机制 - 由客户端负责

详见 [协议边界与免责声明](./skynet.md#10-协议边界与免责声明)。

## 核心概念

### 1. 核心标识
Skynet 协议有三个核心标识：
- **auth_id**：用户全局身份 ID，跨子网唯一，类似真名。**Skynet 协议的最高机密，仅用于身份认证，绝不应在子网内部数据中泄露或存储。**
- **user_id**：用户在子网内的本地 ID，类似昵称/网名，用于隐私保护。**子网内部所有数据只使用 user_id。**
- **subnet_id**：子网唯一 ID，标识一个独立的通信系统

### 2. 子网模型
Skynet 采用子网模型，每个独立的通信系统或社区都是一个子网：
- 每个子网有自己的用户、联系人、群组
- 用户可以同时加入多个子网，使用同一个 `auth_id`
- 每个子网有独立的联系人和群组（联系人是子网内部概念）

### 3. 去中心化架构
Skynet 采用两级网络结构：
- **主网**：由服务节点组成的对等网络，负责节点发现和网络路由
- **子网**：独立的通信系统，隔离不同平台的数据

### 4. 服务节点
- 每个节点拥有独立的 Ed25519 密钥对和唯一的 NodeID
- 节点通过 Kademlia DHT 进行网络发现和地址存储
- 支持 STUN/TURN 协议处理 NAT 穿透

### 5. 子网
子网是独立的通信系统：
- 每个子网有唯一的 subnet_id
- 由一组维护节点负责数据存储和同步
- 支持成员管理、频道（channel）等子网内部功能

### 6. 资源（Resource）
资源是子网内可访问的实体：
- 资源有唯一的资源 ID（resource_id）
- 资源可以是文件、图片、文档、链接等
- 资源可以被授权访问和管理
- 支持资源版本控制和历史记录
- **不跨子网共享**：资源仅在所属子网内可访问，如需跨子网使用必须复制

### 7. 信息（Message）
信息是子网内传递的内容单元：
- 信息有唯一的消息 ID（message_id）
- 信息内容是**结构化数据**（JSON 对象），不是固定的 Markdown 或 HTML 格式
- 客户端根据消息类型和内容结构自主决定如何渲染
- 信息支持端到端加密
- 信息可以在频道或私聊中发送
- **不跨子网传递**：消息不跨子网，如需转发必须复制到目标子网
- **可选消息状态**：支持已送达、已读等状态跟踪（可选扩展）

### 8. 消息表情反应（Reaction）
消息表情反应是用户对消息的情感反馈：
- 用户可以对消息添加表情反应（如 👍、❤️、🎉 等）
- 支持自定义表情
- 可查看哪些用户添加了哪个表情
- 可撤销自己添加的反应

### 9. 消息置顶（Pin）
消息置顶用于标记重要消息：
- 可将重要消息置顶到频道或私聊顶部
- 支持多条消息置顶
- 置顶消息按时间排序或手动排序
- 只有管理员或消息发送者可置顶（可配置）

### 10. 消息线程（Thread）
消息线程用于在消息下进行深入讨论：
- 可在任意消息下创建回复线程
- 线程消息独立显示，不影响主聊天流
- 支持线程内消息通知
- 可折叠/展开线程

### 11. 消息提及（Mention）
消息提及用于提醒特定用户：
- **@用户**：提及特定用户，该用户会收到通知
- **@所有人**：提及频道所有成员
- **@角色**：提及特定角色的所有成员（如 @管理员）
- 被提及的消息会高亮显示

### 12. 用户元信息（Profile）
用户元信息描述用户的公开信息：
- 头像（avatar）：用户头像图片或哈希
- 昵称（nickname）：用户在子网内的显示名称
- 个人简介（bio）：用户的个人简介
- 自定义状态文本（status_text）：用户的自定义状态文本
- 在线状态（presence_status）：用户的在线状态（在线/忙碌/离开/离线）
- 最后活跃时间（last_active_at）：用户最后活跃的时间
- 元信息是公开的，存储在子网成员列表中

### 13. 零信任安全
- 所有关键操作均需密码学签名验证
- 服务节点之间、客户端与服务端之间互不信任
- 端到端加密确保只有通信双方能够解密内容

### 关系图

```
去中心化设计理念（architecture/）
    ↓ 指导

    ↓ 实现

```

### 具体对应

| 设计理念 | Skynet 实现 |
|---------|-----------|
| 零信任架构 | auth_id 身份验证、端到端加密、相互不信任假设 |
| 去中心化 | 对等网络、主网-子网两级结构、无单点故障 |
| 可验证计算 | 数字签名、多节点交叉验证、拜占庭容错 |
| 数据主权 | 端到端加密、用户控制密钥、服务端无法访问明文 |
