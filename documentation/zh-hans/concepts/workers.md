# 工作节点

## 核心概念

### 工作节点（Worker Node）

**工作节点**是 AI Company 系统中的基本计算单元，**每一台物理或虚拟设备都是一个独立的工作节点**。

工作节点为工作区提供运行环境，一个工作区可以同时在多个工作节点上运行，每个节点上有该工作区的一个实例。

#### 工作节点类型

系统支持以下类型的工作节点：

| 节点类型 | 描述 | 典型场景 | 特点 |
|---------|------|---------|------|
| **Windows 个人 PC** | 桌面端设备 | 日常办公、内容创作 | 高性能、大屏幕、完整输入设备 |
| **服务器** | 云端或本地服务器 | 后台任务、长期运行服务 | 24/7 运行、高可靠性、多任务处理 |
| **Android 手机** | 安卓移动设备 | 移动办公、即时响应 | 便携性、随时随地访问、传感器丰富 |
| **iOS 手机** | 苹果移动设备 | 移动办公、即时响应 | 便携性、安全性高、生态完善 |
| **平板设备** | Android/iPad 平板 | 内容消费、轻量创作 | 大屏幕、触控友好 |
| **IoT 设备** | 智能硬件 | 特定任务、数据采集 | 专用功能、低功耗 |

#### 工作节点特性

每个工作节点具备以下特性：

1. **独立身份**
   - 每个节点有唯一的节点 ID
   - 支持节点认证和授权
   - 可独立加入或离开系统

2. **本地优先**
   - 优先使用本地计算资源
   - 离线时仍可正常工作
   - 数据同步在后台自动进行

3. **资源发现**
   - 节点自动发现和连接
   - 动态调整节点拓扑
   - 支持节点热插拔

4. **能力声明**
   - 节点声明自己的能力（如 GPU、特定软件、传感器）
   - 任务路由到合适的节点
   - 能力动态更新

## 架构设计

### 节点-工作区层级结构

```
AI Company 系统
│
├── 工作区 A（个人工作区，跨 3 个节点）
│   ├── 工作节点 1 (Windows PC)
│   │   └── 工作区实例 A-1
│   │       ├── 智能体 1
│   │       └── 本地数据缓存
│   ├── 工作节点 2 (Android 手机)
│   │   └── 工作区实例 A-2
│   │       ├── 智能体 2（迁移自节点 1）
│   │       └── 本地数据缓存
│   └── 工作节点 3 (服务器)
│       └── 工作区实例 A-3
│           ├── 智能体 3（后台运行）
│           └── 完整数据副本
│
├── 工作区 B（项目工作区，跨 2 个节点）
│   ├── 工作节点 1 (Windows PC)
│   │   └── 工作区实例 B-1
│   │       └── 智能体 4
│   └── 工作节点 4 (服务器)
│       └── 工作区实例 B-2
│           └── 智能体 5（长期运行）
│
└── 工作区 C（临时工作区，单节点）
    └── 工作节点 2 (Android 手机)
        └── 工作区实例 C-1
            └── 临时任务
```

### 节点间通信

工作节点之间支持自动发现、安全通信和数据同步。详细的技术选型请参考维护者文档中的 [技术选型](../../maintainer/technology-choices.md)。

## 工作节点管理

### 节点注册

1. **首次启动**
   - 节点生成唯一身份密钥对
   - 创建节点配置文件
   - 注册到系统

2. **节点信息**
   ```
   节点信息 {
     id: 节点唯一标识
     name: 节点名称
     type: Windows | Server | Android | iOS
     capabilities: [能力列表]
     status: online | offline | busy
     lastSeen: 最后在线时间
     workspaces: [关联工作区列表]
   }
   ```

### 节点状态

工作节点有多种状态，用于指示其可用性和负载情况。详细信息请参考维护者文档。

### 节点监控

- **资源监控**：CPU、内存、磁盘、网络
- **健康检查**：定期心跳检测
- **性能指标**：任务完成率、响应时间
- **告警机制**：异常情况通知

## 工作区实例管理

每个工作区在关联的节点上都有一个实例：

| 实例状态 | 描述 |
|---------|------|
| **Active** | 实例活跃，正在运行智能体 |
| **Standby** | 实例待命，数据同步中 |
| **Offline** | 节点离线，数据待同步 |
| **Failed** | 实例异常，需要恢复 |

### 实例生命周期

1. **创建**：工作区分配到节点时创建实例
2. **启动**：实例初始化，加载数据
3. **运行**：执行智能体，处理任务
4. **同步**：与其他实例同步数据
5. **停止**：暂停智能体，保存状态
6. **销毁**：从节点移除实例

## 智能体调度

### 节点选择

系统根据以下因素选择合适的工作节点（在工作区范围内）：

1. **能力匹配**：节点是否具备所需能力
2. **资源可用**：节点资源是否充足
3. **网络延迟**：优先选择延迟低的节点
4. **数据位置**：优先选择数据所在的节点
5. **用户偏好**：尊重用户的优先选择
6. **实例状态**：优先选择 Active 状态的实例

### 任务迁移

- **动态迁移**：智能体可在工作区的不同节点间迁移
- **状态保持**：迁移时保持智能体状态和上下文
- **无缝切换**：用户感知不到迁移过程

## 数据管理

### 数据存储层次

1. **实例级**：工作区实例的本地缓存
2. **工作区级**：工作区的共享数据（跨节点同步）
3. **全局级**：跨工作区共享数据

### 数据同步策略

- **实时同步**：重要数据实时同步
- **定期同步**：非关键数据定期同步
- **按需同步**：用户手动触发同步
- **冲突解决**：自动或手动解决冲突

## 安全模型

### 节点安全

- **节点认证**：每个节点都有独立的身份证书
- **安全启动**：节点启动时进行安全校验
- **远程擦除**：丢失设备可远程擦除数据
- **工作区授权**：控制节点可以加入哪些工作区

## 与工作流的关系

工作节点为工作流提供计算资源，工作流的任务可以分派到不同节点执行。根据节点能力和资源自动选择，支持任务在节点间迁移。

详见 [工作流](./workflows.md) 文档了解更多。

## 总结

工作节点和工作区的概念为 AI Company 提供了灵活、高效、安全的分布式计算架构：

- **灵活性**：工作区可跨节点，支持各种设备类型，适应不同场景
- **高效性**：智能调度，资源优化利用，智能体自动迁移
- **安全性**：多层隔离，细粒度权限控制，节点授权
- **用户体验**：无缝切换，离线可用，数据同步

这种设计让用户可以真正拥有和控制自己的计算资源，同时享受分布式系统带来的便利。工作区不再局限于单个设备，而是一个可以跨越节点边界的逻辑实体。
