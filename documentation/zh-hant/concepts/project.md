# 專案（Project）：專案範本

### 概念定義

**專案**是一個具體的任務或目標，有明確的開始和結束時間，以及可衡量的成果。專案範本定義了完成某類專案的標準流程和方法。

### 核心要素

#### 基本資訊
- **專案名稱**：專案的標識性名稱
- **專案描述**：詳細的專案介紹
- **專案狀態**：規劃中 / 進行中 / 已完成 / 已歸檔
- **開始時間**：專案的啟動時間
- **結束時間**：專案的預計完成時間
- **優先級**：低 / 中 / 高 / 緊急

#### 專案結構
- **階段劃分**：專案分為哪些階段（如：需求、設計、開發、測試、上線）
- **里程碑**：關鍵的檢查點和交付物
- **任務分解**：WBS（工作分解結構）
- **相依關係**：任務之間的相依關係

#### 標準作業流程（SOP）
- **階段流程**：每個階段的標準操作步驟
- **交付物清單**：每個階段需要產出的文件和成果
- **驗收標準**：每個階段的完成標準和質量要求
- **審批節點**：需要審批的關鍵節點

#### 資源配置
- **負責團隊**：專案同一時間只能交給一個團隊負責
- **所需技能**：需要哪些技能的員工
- **時間估算**：每個階段的時間預估
- **預算規劃**：專案的預算分配

#### 團隊與子團隊
- **單一團隊負責**：每個專案同一時間只能有一個主負責團隊
- **子團隊呼叫**：主團隊可以根據需要呼叫子團隊
- **靈活組合**：子團隊必須是完整的團隊，即便只有一個員工也要包裝成團隊
- **協作機制**：主團隊和子團隊之間有明確的協作和溝通方式

#### 風險管理
- **風險辨識**：可能遇到的風險
- **應對策略**：風險的應對方案
- **應急預案**：緊急情況的處理預案
- **質量標準**：專案的質量要求

### 專案範本的作用

1. **標準化流程**
   - 同類專案使用相同的流程
   - 減少重複工作，提高效率
   - 確保專案質量的一致性

2. **經驗積累**
   - 成功的專案可以轉化為範本
   - 失敗的經驗可以反映在範本改進中
   - 組織的專案管理能力持續提升

3. **協作效率**
   - 團隊成員清楚每個階段的目標
   - 減少溝通成本
   - 新人可以快速上手

### 範例：產品開發專案範本

```
產品開發專案
├── 階段 1：需求調研
│   ├── 市場分析
│   ├── 使用者訪談
│   ├── 競品分析
│   └── 需求文件
├── 階段 2：產品設計
│   ├── 產品原型
│   ├── UI 設計
│   ├── 互動設計
│   └── 設計評審
├── 階段 3：開發實現
│   ├── 架構設計
│   ├── 程式碼開發
│   ├── 單元測試
│   └── 程式碼審查
├── 階段 4：測試驗證
│   ├── 功能測試
│   ├── 效能測試
│   ├── 使用者測試
│   └── Bug 修復
└── 階段 5：發布上線
    ├── 發布準備
    ├── 灰度發布
    ├── 全量發布
    └── 效果監控
```
