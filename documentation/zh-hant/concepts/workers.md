# 工作節點

## 核心概念

### 工作節點（Worker Node）

**工作節點**是 AI Company 系統中的基本計算單元，**每一台實體或虛擬裝置都是一個獨立的工作節點**。

工作節點為工作區提供執行環境，一個工作區可以同時在多個工作節點上執行，每個節點上有該工作區的一個執行個體。

#### 工作節點類型

系統支援以下類型的工作節點：

| 節點類型 | 描述 | 典型場景 | 特點 |
|---------|------|---------|------|
| **Windows 個人 PC** | 桌面端裝置 | 日常辦公、內容創作 | 高效能、大螢幕、完整輸入裝置 |
| **伺服器** | 雲端或本地伺服器 | 後台任務、長期執行服務 | 24/7 執行、高可靠性、多任務處理 |
| **Android 手機** | 安卓行動裝置 | 行動辦公、即時回應 | 便攜性、隨時隨地存取、感測器豐富 |
| **iOS 手機** | 蘋果行動裝置 | 行動辦公、即時回應 | 便攜性、安全性高、生態完善 |
| **平板裝置** | Android/iPad 平板 | 內容消費、輕量創作 | 大螢幕、觸控友善 |
| **IoT 裝置** | 智慧硬體 | 特定任務、資料擷取 | 專用功能、低功耗 |

#### 工作節點特性

每個工作節點具備以下特性：

1. **獨立身份**
   - 每個節點有唯一的節點 ID
   - 支援節點認證和授權
   - 可獨立加入或離開系統

2. **本地優先**
   - 優先使用本地計算資源
   - 離線時仍可正常工作
   - 資料同步在後台自動進行

3. **資源發現**
   - 節點自動發現和連線
   - 動態調整節點拓撲
   - 支援節點熱插拔

4. **能力宣告**
   - 節點宣告自己的能力（如 GPU、特定軟體、感測器）
   - 任務路由到合適的節點
   - 能力動態更新

## 架構設計

### 節點-工作區層級結構

```
AI Company 系統
│
├── 工作區 A（個人工作區，跨 3 個節點）
│   ├── 工作節點 1 (Windows PC)
│   │   └── 工作區執行個體 A-1
│   │       ├── 智慧體 1
│   │       └── 本地資料快取
│   ├── 工作節點 2 (Android 手機)
│   │   └── 工作區執行個體 A-2
│   │       ├── 智慧體 2（遷移自節點 1）
│   │       └── 本地資料快取
│   └── 工作節點 3 (伺服器)
│       └── 工作區執行個體 A-3
│           ├── 智慧體 3（後台執行）
│           └── 完整資料副本
│
├── 工作區 B（專案工作區，跨 2 個節點）
│   ├── 工作節點 1 (Windows PC)
│   │   └── 工作區執行個體 B-1
│   │       └── 智慧體 4
│   └── 工作節點 4 (伺服器)
│       └── 工作區執行個體 B-2
│           └── 智慧體 5（長期執行）
│
└── 工作區 C（臨時工作區，單節點）
    └── 工作節點 2 (Android 手機)
        └── 工作區執行個體 C-1
            └── 臨時任務
```

### 節點間通訊

工作節點之間支援自動發現、安全通訊和資料同步。詳細的技術選型請參考維護者文件中的 [技術選型](../../maintainer/technology-choices.md)。

## 工作節點管理

### 節點註冊

1. **首次啟動**
   - 節點產生唯一身份金鑰對
   - 建立節點設定檔
   - 註冊到系統

2. **節點資訊**
   ```
   節點資訊 {
     id: 節點唯一標識
     name: 節點名稱
     type: Windows | Server | Android | iOS
     capabilities: [能力列表]
     status: online | offline | busy
     lastSeen: 最後在線時間
     workspaces: [關聯工作區列表]
   }
   ```

### 節點狀態

工作節點有多種狀態，用於指示其可用性和負載情況。詳細資訊請參考維護者文件。

### 節點監控

- **資源監控**：CPU、記憶體、磁碟、網路
- **健康檢查**：定期心跳偵測
- **效能指標**：任務完成率、回應時間
- **告警機制**：異常情況通知

## 工作區執行個體管理

每個工作區在關聯的節點上都有一個執行個體：

| 執行個體狀態 | 描述 |
|---------|------|
| **Active** | 執行個體活躍，正在執行智慧體 |
| **Standby** | 執行個體待命，資料同步中 |
| **Offline** | 節點離線，資料待同步 |
| **Failed** | 執行個體異常，需要復原 |

### 執行個體生命週期

1. **建立**：工作區分配到節點時建立執行個體
2. **啟動**：執行個體初始化，載入資料
3. **執行**：執行智慧體，處理任務
4. **同步**：與其他執行個體同步資料
5. **停止**：暫停智慧體，儲存狀態
6. **銷毀**：從節點移除執行個體

## 智慧體排程

### 節點選擇

系統根據以下因素選擇合適的工作節點（在工作區範圍內）：

1. **能力匹配**：節點是否具備所需能力
2. **資源可用**：節點資源是否充足
3. **網路延遲**：優先選擇延遲低的節點
4. **資料位置**：優先選擇資料所在的節點
5. **使用者偏好**：尊重使用者的優先選擇
6. **執行個體狀態**：優先選擇 Active 狀態的執行個體

### 任務遷移

- **動態遷移**：智慧體可在工作區的不同節點間遷移
- **狀態保持**：遷移時保持智慧體狀態和上下文
- **無縫切換**：使用者感知不到遷移過程

## 資料管理

### 資料儲存層次

1. **執行個體級**：工作區執行個體的本地快取
2. **工作區級**：工作區的共享資料（跨節點同步）
3. **全域級**：跨工作區共享資料

### 資料同步策略

- **即時同步**：重要資料即時同步
- **定期同步**：非關鍵資料定期同步
- **按需同步**：使用者手動觸發同步
- **衝突解決**：自動或手動解決衝突

## 安全模型

### 節點安全

- **節點認證**：每個節點都有獨立的身份憑證
- **安全啟動**：節點啟動時進行安全校驗
- **遠端擦除**：遺失裝置可遠端擦除資料
- **工作區授權**：控制節點可以加入哪些工作區

## 與工作流程的關係

工作節點為工作流程提供計算資源，工作流程的任務可以分派到不同節點執行。根據節點能力和資源自動選擇，支援任務在節點間遷移。

詳見 [工作流程](./workflows.md) 文件了解更多。

## 總結

工作節點和工作區的概念為 AI Company 提供了靈活、高效、安全的分散式計算架構：

- **靈活性**：工作區可跨節點，支援各種裝置類型，適應不同場景
- **高效性**：智慧排程，資源優化利用，智慧體自動遷移
- **安全性**：多層隔離，細粒度權限控制，節點授權
- **使用者體驗**：無縫切換，離線可用，資料同步

這種設計讓使用者可以真正擁有和控制自己的計算資源，同時享受分散式系統帶來的便利。工作區不再局限於單個裝置，而是一個可以跨越節點邊界的邏輯實體。
