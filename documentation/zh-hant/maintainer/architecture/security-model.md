# 安全模型

本文件描述 AI Company 作為 Skynet 協定上的一種子網實現，如何在架構層面補充安全機制。

## 概述

### 分層職責劃分

| 層級 | 負責內容 | 說明 |
|------|---------|------|
| **Skynet 協定層** | 網路通訊、基礎密碼學原語、子網抽象 | 輕量化、靈活、通用 |
| **子網實現層（AI Company）** | 特定場景的安全機制、客戶端實現指南 | 根據子網型別按需實現 |

Skynet 協定只定義**最小必要**的安全機制，保持輕量化和靈活性。具體子網（如 AI Company）根據自身需求在架構層補充額外的安全措施。

---

## 一、中繼資料保護

### Skynet 協定層定位
Skynet 協定**不提供**中繼資料保護，保持協定輕量化。

### AI Company 子網層負責實現

對於企業級應用，中繼資料保護方案由 AI Company 負責設計和實現：

#### 基線措施（推薦）
| 措施 | 說明 |
|------|------|
| **路由隨機化** | 客戶端隨機選擇服務節點 |
| **時間戳精度降低** | 秒級精度（而非毫秒） |

#### 長期規劃：混合網路
如需強中繼資料保護，AI Company 可在未來版本引入混合網路（如 Loopix），但這需要：
- 顯著的架構變更
- 接受更高的延遲和頻寬開銷
- 僅適用於隱私要求極高的場景

## 二、抗量子密碼學（PQC）遷移

### Skynet 協定層定位
Skynet 協定**預留擴展點**，支援 PQC 演算法遷移，但不強制要求。

### AI Company 子網層負責實現

#### 2.1 混合憑證模式
AI Company 負責實現同時支援經典密碼學和後量子密碼學：
- **雙金鑰對**：每個身份同時持有 Ed25519 和 CRYSTALS-Dilithium 金鑰對
- **雙簽章**：重要操作同時使用兩種演算法簽章
- **漸進遷移**：先支援驗證，再逐步切換到 PQC 為主

#### 2.2 PQC 密碼套件
| 元件 | 經典演算法 | PQC 演算法 | 混合模式 |
|------|---------|---------|---------|
| **簽章** | Ed25519 | CRYSTALS-Dilithium | Ed25519 + Dilithium |
| **金鑰封裝** | X25519 | CRYSTALS-Kyber | X25519 + Kyber |
| **雜湊** | Blake3 | Blake3 | Blake3 |

#### 2.3 金鑰輪換策略
- **緊急輪換**：發現量子威脅時可立即觸發全網路金鑰輪換
- **定期輪換**：預設每 90 天輪換一次長期金鑰
- **前向安全**：工作階段金鑰使用 PQC KEM 確保前向安全

### 遷移路線圖
```
階段 1（當前）：經典密碼學為主
    ↓
階段 2：混合模式（同時支援經典和 PQC）
    ↓
階段 3：PQC 為主，經典作為備選
    ↓
階段 4：完全 PQC（移除經典演算法支援）
```

## 三、客戶端安全實現指南（AI Company 子網層）

### Skynet 協定層定位
Skynet 協定**定義介面**，但將具體實作交給客戶端和子網層。

### AI Company 子網層規範

#### 3.1 金鑰管理規範

##### 金鑰儲存層級
| 金鑰型別 | 儲存位置 | 加密保護 |
|---------|---------|---------|
| **身份私鑰** | 系統金鑰鏈 / HSM / TEE | 硬體級保護 |
| **設備私鑰** | 加密的本地儲存 | 用戶密碼派生金鑰 |
| **工作階段金鑰** | 記憶體（程序隔離） | 自動銷毀 |

##### 金鑰派生要求
- **演算法**：強制使用 Argon2id
- **參數**：
  - 記憶體：至少 64MB
  - 迭代次數：至少 3 次
  - 平行度：4
  - 鹽值：16 位元組 CSPRNG 產生

##### 金鑰備份與復原
- **Shamir 秘密分享**：將復原金鑰分成 5 份，3 份可復原
- **離線儲存**：鼓勵用戶將復原金鑰列印或儲存在離線裝置
- **社交復原**：可選支援信任聯絡人協助復原

#### 3.2 API Key 管理規範（AI Company 特定）

##### API Key 安全原則
| 原則 | 說明 |
|------|------|
| **最小權限** | 每個 API Key 只授予完成任務所需的最小權限 |
| **短暫有效** | 優先使用短期 Token，而非永久 API Key |
| **隔離使用** | 不同 Agent/服務使用不同的 API Key |
| **可撤銷** | 隨時可撤銷外洩或不再需要的 API Key |

##### API Key 儲存
- **儲存位置**：系統金鑰鏈 / 安全金鑰管理服務（KMS）
- **加密保護**：靜態加密，使用主金鑰加密 API Key
- **記憶體保護**：使用後立即從記憶體清除，避免交換到磁碟

##### API Key 生命週期管理
```
建立 → 分發 → 使用 → 輪換 → 撤銷 → 銷毀
```

**建立**：
- 使用 CSPRNG 產生足夠強度的 API Key（至少 256 位熵）
- 記錄建立時間、建立者、用途、權限範圍

**分發**：
- 安全通道傳輸（端到端加密）
- 避免在日誌、錯誤訊息中暴露完整 API Key
- 僅顯示 Key 的前/後幾位用於識別

**使用**：
- 透過環境變數或安全設定檔案注入，而非硬編碼
- 使用請求標頭或授權欄位傳遞（如 `Authorization: Bearer <key>`）
- 避免在 URL 查詢參數中傳遞

**輪換**：
- 定期輪換（預設 90 天）
- 支援新舊 Key 共存過渡期（至少 7 天）
- 觸發安全事件時立即輪換

**撤銷**：
- 提供自助撤銷介面
- 撤銷後立即失效
- 記錄撤銷原因和時間

**銷毀**：
- 從所有儲存位置刪除
- 覆蓋記憶體和磁碟中的殘留
- 驗證銷毀完成

##### API Key 外洩應急回應
1. **立即撤銷**：發現外洩後第一時間撤銷
2. **稽核日誌**：檢查該 Key 的所有使用記錄
3. **影響評估**：評估外洩可能造成的損失
4. **通知用戶**：通知受影響的用戶/團隊
5. **根因分析**：找出外洩原因，防止再次發生
6. **安全加固**：改進儲存和使用方式

##### 臨時 Token 優先
對於 Agent 場景，優先使用短期 Token 而非永久 API Key：
- **OAuth 2.0**：使用 Client Credentials 或 Authorization Code Flow
- **JWT**：短期 JWT Token（有效期 < 1 小時）
- **動態刷新**：使用 Refresh Token 取得新的 Access Token

#### 3.3 隨機數產生規範

##### 熵源要求
- **主要熵源**：作業系統 CSPRNG（Windows: `CryptGenRandom`, Linux: `/dev/urandom`）
- **補充熵源**：
  - 設備感測器資料（加速度計、陀螺儀）
  - 用戶互動時間戳
  - 網路延遲測量
- **熵混合**：使用 Fortuna 或 Yarrow 演算法混合多源熵

##### CSPRNG 驗證
- 實現 NIST SP 800-90A 標準
- 定期進行隨機性測試（Dieharder、TestU01）
- 禁止使用任何非密碼學安全的隨機數產生器

#### 3.4 參考實現（AI Company 子網 SDK）
提供官方 SDK，包含：
- **加密庫封裝**：統一的密碼學原語介面
- **金鑰管理模組**：開箱即用的安全金鑰儲存
- **API Key 管理模組**：安全的 API Key 生命週期管理

## 四、安全稽核與日誌（AI Company 負責）

### Skynet 協定層定位
稽核日誌**不納入 Skynet 協定**，完全由子網建立者根據需求自主實現。

### 原因
不同子網型別的稽核需求差異極大：

| 子網型別 | 稽核需求 | 範例 |
|---------|---------|------|
| **組織子網（AI Company）** | 高要求 | 完整稽核日誌、不可竄改、多年保留、合規認證 |
| **社群子網** | 中要求 | 基礎操作日誌、可選保留 |
| **私有子網** | 低要求 | 可能不需要任何稽核日誌 |

### AI Company 子網負責實現

AI Company 作為企業級子網，負責實現完整的稽核日誌功能：

#### 4.1 稽核事件型別
- 身份認證事件
- 金鑰/API Key 操作
- 權限變更
- 敏感資源存取

#### 4.2 日誌安全要求
- **客戶端本地儲存**：稽核日誌由客戶端收集和儲存
- **加密保護**：敏感稽核日誌加密儲存
- **完整性保護**：使用數位簽章防止竄改
- **子網級設定**：子網建立者可定義稽核策略

## 五、女巫攻擊防護（AI Company 負責）

### Skynet 協定層定位
Skynet 協定**不強制**女巫攻擊防護，保持協定靈活性。

### AI Company 子網層負責實現

#### 5.1 多層防護體系

| 防護層級 | 機制 | 說明 |
|---------|------|------|
| **第一層** | 身份驗證 | 郵箱、手機號、WebAuthn 等 |
| **第二層** | 工作量證明 | Hashcash 或類似機制 |
| **第三層** | 社交圖譜驗證 | 信任聯絡人背書 |
| **第四層** | 經濟抵押 | 鎖定 Token 作為保證金 |

#### 5.2 身份驗證選項
- **WebAuthn/FIDO2**：推薦的強認證方式
- **郵箱驗證**：發送驗證連結
- **手機號驗證**：簡訊驗證碼
- **OAuth**：支援第三方身份提供商（Google、GitHub 等）

#### 5.3 信譽系統
- **初始信譽**：新用戶低信譽，限制操作頻率
- **信譽積累**：正常使用逐漸提高信譽
- **信譽懲罰**：惡意行為降低信譽
- **跨子網信譽**：信譽可在不同子網間共享

## 六、前向保密強化（子網層實現指南）

### Skynet 協定層定位
Skynet 協定**使用** Double Ratchet 和 MLS 提供前向保密，但具體實作細節由客戶端負責。

### AI Company 子網層規範

#### 6.1 金鑰銷毀規範

##### 記憶體金鑰銷毀
- **零覆蓋**：使用 memset_s 或等效函式覆蓋金鑰記憶體
- **多次覆蓋**：至少 3 次不同模式覆蓋
- **記憶體鎖定**：使用 mlock/VirtualLock 防止金鑰交換到磁碟

##### 持久化金鑰銷毀
- **安全刪除**：使用 shred 或等效工具
- **SSD 處理**：針對 SSD 特殊處理（TRIM、安全擦除）
- **驗證銷毀**：確認金鑰材料已無法復原

#### 6.2 前向保密保證
- **工作階段金鑰短命**：每次訊息輪換金鑰（Double Ratchet）
- **無金鑰快取**：不快取任何可用於解密舊訊息的金鑰
- **完美前向保密（PFS）**：明確保證 PFS 屬性

## 七、安全邊界與縱深防禦（AI Company 子網層）

### 7.1 安全邊界定義

| 邊界 | 保護措施 |
|------|---------|
| **客戶端邊界** | 沙箱隔離、程序隔離、記憶體保護 |
| **網路邊界** | TLS 1.3、憑證鎖定、憑證透明度 |
| **服務節點邊界** | 最小權限、網路隔離、入侵檢測 |
| **資料邊界** | 端到端加密、靜態加密、存取控制 |

### 7.2 縱深防禦策略

```
第一層：客戶端安全
    ↓
第二層：傳輸安全（TLS 1.3 + Noise）
    ↓
第三層：端到端加密（X3DH + Double Ratchet / MLS）
    ↓
第四層：多節點驗證
    ↓
第五層：稽核日誌與異常檢測（可選）
```

## 八、安全合規與認證（AI Company 子網層）

### 8.1 合規標準（按需滿足）
- **GDPR**：資料保護、用戶控制權、可攜性
- **HIPAA**（如適用）：醫療資料保護
- **SOC 2**：安全、可用性、保密性
- **ISO 27001**：資訊安全管理體系

### 8.2 安全認證（可選）
- **第三方稽核**：定期進行獨立安全稽核
- **漏洞賞金**：建立漏洞賞金計畫
- **公開透明**：公開安全稽核報告

## 總結

### 分層職責回顧

| 層級 | 職責 |
|------|------|
| **Skynet 協定層** | 提供輕量化、靈活的基礎：密碼學原語、網路通訊、子網抽象 |
| **AI Company 子網層** | 企業級安全實現：API Key 管理、稽核日誌、合規認證等 |

### 明確責任劃分

| 安全領域 | Skynet 協定 | AI Company |
|---------|------------|------------|
| **中繼資料保護** | 不提供 | 負責實現 |
| **抗量子破解** | 預留擴展點 | 負責實現 |
| **API Key 管理** | 不涉及 | 負責 |
| **稽核日誌** | 不納入 | 負責 |
| **女巫防護** | 不強制 | 負責 |

### AI Company 安全模型補充

作為 Skynet 上的企業級子網實現，AI Company 安全模型透過以下方式補充協定層：

1. **中繼資料保護**：AI Company 負責實現，提供基線措施和長期規劃
2. **抗量子遷移**：AI Company 負責實現，混合憑證模式、漸進遷移路線圖
3. **客戶端安全**：金鑰管理規範、API Key 管理規範、隨機數產生規範、官方 SDK
4. **稽核日誌**：AI Company 負責實現，完整稽核日誌功能
5. **女巫防護**：AI Company 負責實現，多層防護、身份驗證、信譽系統
6. **前向保密**：金鑰銷毀規範、PFS 保證
7. **合規認證**：GDPR、SOC 2、ISO 27001

二者結合，構成完整的企業級安全體系，同時保持 Skynet 協定本身的輕量化和靈活性。
