# ys-storage

`ys-storage` 是源神项目的存储抽象层，提供了统一的接口来处理对象（Object）和分支（Branch）的存储。

## 存储方案及应用场景

本库提供了三种不同的存储后端，以适应不同的开发和生产需求：

### 1. 纯内存方案 (In-Memory)
- **实现类**: `MemoryObjectPool` ([in_memory.rs](src/in_memory.rs))
- **特点**: 
    - 数据完全存储在内存的 `DashMap` 中。
    - **停止服务后数据全部消失**。
    - 读写速度极快，无需磁盘 I/O。
- **应用场景**: 
    - **单元测试**: 避免测试过程中产生磁盘垃圾文件。
    - **集成测试**: 需要快速重置状态的场景。
    - **临时演示**: 不需要持久化数据的临时运行环境。

### 2. 本地文件系统方案 (Local File System)
- **实现类**: `LocalDotYuanShen` ([file_system.rs](src/file_system.rs))
- **特点**: 
    - 使用类似 Git 的 `.yuanshen` 目录结构存储数据。
    - 数据持久化在本地磁盘。
    - 结构简单，易于手动检查和维护。
- **应用场景**: 
    - **个人开发环境**: 简单的本地数据持久化。
    - **小型工具**: 不需要复杂数据库支持的场景。

### 3. Limbo + FS 混合方案 (Limbo & File System)
- **实现类**: `LimboFsStorage` ([limbo_fs.rs](src/limbo_fs.rs))
- **特点**: 
    - **元数据管理**: 使用 Limbo (高性能 SQLite 实现) 存储分支信息、配置等结构化数据。
    - **对象存储**: 大文件对象依然存储在文件系统中，通过哈希分片管理。
    - 兼顾了数据库的查询能力和文件系统处理大文件的优势。
- **应用场景**: 
    - **生产/模拟生产环境**: 需要可靠的元数据管理和高效的对象存储。
    - **复杂版本管理**: 分支较多、元数据操作频繁的场景。

## 如何选择
- **写测试?** 选 **Memory**。
- **快速原型开发?** 选 **FileSystem**。
- **正式环境/高性能需求?** 选 **Limbo + FS**。
